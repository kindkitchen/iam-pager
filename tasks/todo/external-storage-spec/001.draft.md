# External storage specification - draft scope

## Goal

One specification document that later tasks implement without re-deciding
product questions.

## Scope

1. **Concept definitions**
   - `external content source`: a reference (provider id + connection id +
     provider-native file reference + integrity hint) stored in asset
     metadata; bytes fetched from the provider.
   - `storage connection`: a creator-owned link to one provider account,
     established via OAuth, revocable on either side.
   - Invariant: metadata (pages, locators, policies, asset records, revisions,
     tags) is always local; only content bytes may be external.

2. **Lifecycle** - connect storage; publish/replace a page selecting an
   external source; provider-side deletion/permission loss; owner repair
   (re-link, re-upload locally, detach reference); disconnect storage (decide:
   block while assets depend on it vs mark all dependents missing).

3. **Failure semantics** (drives `external-content-delivery-fallback`)
   - Distinguish `missing` (deleted / permission revoked) from `unreachable`
     (provider outage, rate limit). Missing -> placeholder + owner warning;
     unreachable -> retry/stale-cache policy, NOT marked missing.
   - Visitor view for missing: graceful placeholder ("content temporarily
     unavailable") per the user request; reconcile with the non-disclosing 404
     invariant - the page itself is still public and known, only bytes are
     gone, so placeholder does not leak private existence. Record as decision.
   - Owner view: explicit warning with cause and repair actions.

4. **Security** - OAuth client for Drive is registered separately from
   sign-in (own client id/secret, own redirect URIs, minimal Drive scopes,
   e.g. `drive.file`); tokens encrypted at rest; scopes never widened
   silently; provider tokens never exposed via API or management payloads.

5. **Non-goals v1** - no background sync, no provider-side editing pipeline,
   no multi-account-per-provider (single connection per provider per user
   first), no content migration tooling.
