# Google Drive provider - draft design

## Shape

```
lib/external-storage/
  google-drive-provider.ts        # ExternalStorageProvider implementation
  google-drive-gateway.ts         # thin Drive REST client behind an interface
  google-drive-fake-server.ts     # test-only fake (files.get/create/media)
```

Provider depends on: `StorageConnectionRepository` (credentials + refresh),
`GoogleDriveGateway` (HTTP). Both injected - no direct fetch in the provider.

## Drive API mapping (v3)

- `fetch_content`: `GET files/{id}?alt=media` (+ `supportsAllDrives=true`).
- `stat_content`: `GET files/{id}?fields=id,name,mimeType,size,md5Checksum,trashed`.
  `trashed: true` counts as `external_content_missing` (user "deleted"
  outside the app even if recoverable from trash) - matches the request's
  deletion scenario.
- `put_content`: multipart upload `POST upload/drive/v3/files?uploadType=multipart`
  into an app-managed folder; returns file id -> `ExternalContentRef` with
  `integrity` = md5Checksum.

## Error mapping (load-bearing)

| Drive response                          | Interface result                |
| --------------------------------------- | ------------------------------- |
| 404, 410, `trashed: true`               | `external_content_missing`      |
| 401 after refresh, `invalid_grant`      | `connection_revoked`            |
| 403 permission denied on the file       | `external_content_missing`      |
| 429, 5xx, network error, timeout        | `external_source_unreachable`   |
| anything else                           | `provider_error` with detail    |

Token handling: access token cached with expiry; single-flight refresh via
stored refresh token; refresh failure with `invalid_grant` marks the
connection revoked (repository status update).
