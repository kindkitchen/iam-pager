# External content storage - epic draft

## Request

Extend the platform with integrations that let a user connect their own
storages. Google Drive is the first provider, but the feature must be
implemented interface-first so new providers (GitHub repository, etc.) are
additive. Constraints from the request:

- All metadata stays on our side; only content bytes may live in the user's
  external storage.
- Reuse the existing google auth lib (`@kindkitchen/gauth`) but register it
  explicitly with a different login (OAuth client) and different redirect URIs
  than sign-in.
- Create a provider interface; update existing content models to indicate that
  a content source is located externally (Google Drive).
- Fallback mechanism for content deleted outside the application: graceful
  not-found for visitors, warning for the owner, mock/placeholder content
  until the owner fixes it.

## Grounding in the current codebase

- Auth strategy pattern to mirror: `lib/auth/interfaces.ts`
  (`AuthenticationStrategy`, `AuthenticationStrategyResolver`),
  `lib/auth/strategy-registry.ts`, env-driven composition in
  `lib/auth/google-gauth-composition.ts` (`IAM_PAGER_GOOGLE_AUTH_*`), local
  mock consent in `lib/auth/google-mock-consent-http.ts`.
- Content model to extend: `lib/content/asset.ts` (`ContentAsset`,
  `content_asset_violation`), `lib/content/model.ts` (`ContentMeta`,
  `DeliveryPayload`), `lib/content/interfaces.ts` (`ContentTypeHandler`).
- Persistence: `lib/storage/kv-content-asset-repository.ts`,
  `lib/storage/content-data-codec.ts`, conformance-suite pattern in
  `lib/auth/identity-repository-conformance.ts` and
  `lib/page/aggregate-repository-conformance.ts`.
- Delivery: `lib/page/delivery-http.ts`, `lib/page/service.ts`; visitor
  invariant: missing/private/invalid/unauthorized share a non-disclosing 404.

## Chain rationale

Interface and asset model land before any provider so the domain change is
provider-agnostic. Connection model and OAuth land before the Drive provider
because the provider consumes connections/tokens. Delivery fallback lands
before UI so the dangerous path (external deletion) is handled ahead of
exposure. Management surface is last: it only composes finished capabilities.
