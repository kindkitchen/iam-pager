# External delivery + fallback - draft design

## Behavior matrix (from the request + spec task)

| Event on fetch                  | Visitor sees                          | State recorded                       |
| ------------------------------- | ------------------------------------- | ------------------------------------ |
| ok                              | content, cached local meta            | clears `external_missing` if set     |
| `external_content_missing`      | placeholder page ("temporarily unavailable"), 200 with no-store OR soft-404 per spec decision | `external_missing` + cause + time    |
| `connection_revoked`            | same placeholder                      | `external_missing`, cause revoked    |
| `external_source_unreachable`   | 503 + Retry-After (or stale cache if spec allows) | none - transient                     |

The request wording: "graceful not found and warning for owner (some mock
content till user's fix)". So the visitor-facing artifact is mock content,
not the bare non-disclosing 404; the spec task fixes the exact status code.

## Design points

- Resolution lives in `lib/page/service.ts` behind the existing delivery
  use case; `delivery-http.ts` stays transport-only. Provider resolved via
  `ExternalStorageProviderResolver`; unknown provider id (unregistered env)
  behaves as unreachable, not missing.
- Missing state: new field on the page aggregate/management row
  (`external_missing: { cause, detected_at } | null`) - NOT on the immutable
  asset. Update via existing aggregate repository; both memory and KV pass
  updated conformance.
- Placeholder: `lib/content/external-missing-placeholder.ts` implementing
  `ContentTypeHandler` - bounded static md/html explaining the content is
  temporarily unavailable; no leak of provider, connection, or file details
  to visitors.
- Delivery profiles: placeholder supports `inline` only; `attachment`
  requests for missing content get the spec-decided not-found shape.
- Concurrency: two simultaneous visitor hits on missing content must not
  double-write state (idempotent update).

## Work items

2. Delivery resolution for external assets + tests using the memory provider

3. Placeholder content handler + tests.
4. HTTP-level tests in `lib/page/http.ts` suites: visitor GET on missing
   external content renders placeholder, headers correct, no metadata leak.
5. Recovery-path test: provider restored -> next fetch clears state and
   serves real bytes.
6. Docs (specification failure-semantics section) + CHANGELOG.

## Acceptance

- Behavior matrix fully test-covered at service and HTTP level.
- Inline delivery path provably unchanged (existing delivery tests untouched
  and green).
