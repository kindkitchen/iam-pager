# Fail closed instead of losing page state

Alias mutation was exonerated: page reference updates preserve `content_asset_id` and commit the aggregate and endpoint projections atomically. A new Deno KV regression adds an alias, reconstructs the repository, and verifies the page, alias, and immutable asset.

The runtime now requires explicit ownership, session, and page backend selectors before configured service composition. `deno task dev` explicitly chooses memory. The former `IAM_PAGER_CONTENT_STORAGE_BACKEND` remains a compatible page selector; conflicting old/current selectors fail. Documentation now states that `DENO_KV_ID` and `DENO_KV_ACCESS_TOKEN` do not select repositories and that remote CLI use needs the complete connect URL as `IAM_PAGER_OWNERSHIP_DENO_KV_PATH`.

Read-only audits found no page or content-asset records in either the configured remote KV or the local default KV, so state already lost with the memory process cannot be recovered from those databases.

Verification: `deno task verify` passes 666 tests and all format/lint/type checks; `deno task build` passes; the development server reaches ready state with its explicit memory composition.
