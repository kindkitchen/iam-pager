# Google Drive OAuth connection - draft design

## Constraint from request

Reuse the same lib as sign-in (`@kindkitchen/gauth` 0.4.1) but register it
explicitly as a second composition: different OAuth client ("other login"),
different redirect URIs, different scopes. Sign-in composition
(`lib/auth/google-gauth-composition.ts`, `IAM_PAGER_GOOGLE_AUTH_*`) stays
untouched.

## Environment (new namespace)

- `IAM_PAGER_GOOGLE_DRIVE_MODE` (local | original)
- `IAM_PAGER_GOOGLE_DRIVE_CLIENT_ID` / `_CLIENT_SECRET`
- `IAM_PAGER_GOOGLE_DRIVE_REDIRECT_URI`
- `IAM_PAGER_GOOGLE_DRIVE_MOCK_CONSENT_URL` (local mode)
- `IAM_PAGER_GOOGLE_DRIVE_REQUEST_HOST_PATTERN` (dynamic local, mirroring
  auth)

Scopes: `https://www.googleapis.com/auth/drive.file` only (files the app
created/opened) + offline access (`access_type=offline`, `prompt=consent`) to
obtain a refresh token. Do NOT request full `drive` scope in v1; record a
decision entry if this proves insufficient.

## Flow

1. `GET routes/auth/storage/google-drive/start` - requires authenticated
   session; generates state (reuse `AuthenticationStateGenerator` pattern),
   binds state -> user_id server-side, redirects to consent.
2. `GET routes/auth/storage/google-drive/callback` - validates state,
   exchanges code, reads subject via userinfo/id token, upserts
   `StorageConnection` + credentials via the step-4 repository. Errors render
   an owner-facing "connection failed" page, never a stack.
3. `POST routes/auth/storage/google-drive/disconnect` - revokes token at
   Google (best effort), marks connection revoked locally.

## Local mock mode

Mirror `lib/auth/google-mock-consent-http.ts`: a mock consent screen +
token/userinfo endpoints so `deno task test` and local dev run the full
connect flow offline. Reuse the existing mock where the lib allows;
otherwise a sibling `google-drive-mock-consent-http.ts`.

## Work items

1. Composition module + env parsing + tests (mirror the auth composition
   tests, including host-pattern validation).
2. State handling bound to the session user (storage-connect state must not
   be interchangeable with sign-in state - separate KV prefix).
3. Routes (start/callback/disconnect) + route tests incl. unauthenticated
   rejection and state-mismatch rejection.
4. Disconnect + revocation semantics test (connection kept as `revoked`).
5. `.env` example entries; docs/specification/authentication or
   external-storage doc section; CHANGELOG.

## Acceptance

- Full connect/disconnect roundtrip green in local mock mode.
- Sign-in flow untouched (existing auth tests unchanged and green).
- Redirect URI and client id demonstrably distinct from sign-in via env.
