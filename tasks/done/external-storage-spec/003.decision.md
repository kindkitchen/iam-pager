# Use a 503 placeholder only after page eligibility

Missing or unreachable external bytes return bounded platform-owned HTML with
`503`, `no-store`, and no provider detail. Page visibility is resolved first, so
invalid, absent, private, and unauthorized lookups retain the non-disclosing
`404` invariant. Missing and transient provider failures look the same to a
visitor, while only definitive failures set owner-visible `external_missing`
health.

A `404` for lost bytes was rejected because it conflates a known eligible page
with a missing/private page. A successful `200` placeholder was rejected because
it lies about the asset media type and is cache-prone. Persistent stale-byte
fallback is outside v1.
