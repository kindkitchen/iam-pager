# Separate, encrypt, and explicitly revoke storage credentials

Storage OAuth is separate from sign-in, uses exact callbacks and minimal scopes
(`drive.file` for Drive v1), and requires explicit re-consent for scope growth.
Access and refresh tokens stay server-side under authenticated encryption with
the encryption key outside their database; no API, view model, URL, cookie, or
log exposes them.

Disconnect confirms owner intent, attempts provider revocation, and destroys
local token material even if remote revocation fails. It is allowed while assets
depend on the connection; dependents become `external_missing` and require
repair rather than being silently retargeted. Blocking disconnect was rejected
because it cannot prevent out-of-band provider revocation and would trap an
owner. Automatic retargeting was rejected because provider object identity and
account authority may differ.
