# Correct durable persistence without rewriting product logic

## Problem

The active durable page/content task selected Kvdex as the utility over Deno KV.
The required library is `@kitsonk/kv-toolbox`. The incorrect prototype is not
selected by deployment, but it has one completed immutable-asset slice whose
correctness work must not be discarded casually.

## Goal

Deliver the existing split persistence contracts with kv-toolbox as a pinned,
storage-only implementation detail:

- immutable content assets, including bounded PDF bytes;
- atomic logical pages and complete endpoint sets;
- safe coexistence with and migration from the selected raw Deno KV page schema;
- no Kvdex runtime dependency or endorsed Kvdex design;
- no storage, HTTP, or browser behavior leaking into domain/application logic.

## Working constraints

1. Existing content, page aggregate, endpoint, service, presenter, and HTTP
   interfaces are the authority. Change an interface only to make an existing
   capability boundary explicit, never to expose kv-toolbox.
2. Keep the current raw Deno KV adapter selected until the replacement passes
   unchanged conformance and an explicit migration/cutover gate.
3. Preserve native single-commit compare-and-set semantics for manifest,
   revision, page, owner, and endpoint visibility.
4. Treat multi-batch blob writes as staging only. A payload is unreachable until
   a separately verified manifest is published.
5. Do not migrate, delete, or rewrite production records automatically at
   startup or deploy time.
6. Keep Fresh routes, components, islands, and HTTP responses free of
   kv-toolbox types and decisions.
7. Remove the Kvdex dependency and implementation only after equivalent
   kv-toolbox-backed tests pass, preserving history in git and the rejected task.

## Completion signal

The new durable aggregate satisfies the same contracts as memory, handles the
maximum accepted PDF safely, migrates schema-v1 page fixtures repeatably without
altering the source keyspace, fails rather than presenting an unmigrated database
as empty, and is selected only after all cutover checks pass. See [[004.plan]].
