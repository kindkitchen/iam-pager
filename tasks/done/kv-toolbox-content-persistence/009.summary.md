# Gateway-backed immutable assets replace Kvdex

Phase 2 is complete. `KvContentAssetRepository` now depends only on the
project-owned KV gateway and content-codec interfaces. It snapshots caller-owned
values before its first asynchronous boundary, encodes once with `v8-1`, and
stages detached bytes under random adapter-owned
`iam-pager/content-assets/v1/payloads/<payload_id>` keys.

A strict manifest records schema and encoding versions, asset/payload identity,
encoded length, SHA-256, content metadata, and creation time. Creation reads back
and verifies blob structure, length, hash, decoding, and reconstructed domain
coherence before publishing the manifest under
`iam-pager/content-assets/v1/by-id/<asset_id>` with one native compare-and-set.
Known CAS losses remove staging best-effort. An exception after commit begins is
ambiguous and deliberately retains the payload because a visible manifest may
reference it. Every read repeats all integrity and codec checks.

Focused tests cover immutable isolation, exact manifests, one concurrent winner,
no known staging leaks, fresh repository instances, 1 MiB and accepted 16 MiB
PDF data, later-batch interruption and retry, pre-publication verification
failure, malformed manifests, hash/codec/chunk corruption, ambiguous successful
commit response, and coexistence with the legacy raw page keyspace. The Kvdex
repository, schema factory, imports, and exclusive lock roots are removed.

All 511 tests, tracked-source formatting/lint/type checks, frozen dependency
resolution, and the production build pass. Literal `deno task verify` also scans
the unrelated pre-existing untracked `.pi/extensions/rtk.ts`; it was left
untouched and excluded only from the equivalent tracked-source checks.
Deployment composition, database schema/version, selected raw page adapter, and
stored production records remain unchanged.

Next: Phase 3 from [[004.plan]] — name the aggregate repository capability and
implement native-atomic durable page/envelope, endpoint-claim, owner, and public
indexes over immutable manifest-backed assets, then run shared aggregate
conformance and durable contention/corruption coverage before any migration or
cutover.
