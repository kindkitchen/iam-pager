# Ready to begin development

The active task is implementation-ready. It has an exact dependency target, a
single project-owned KV gateway, an explicit native-atomic safety rule, retained
asset-staging behavior, unchanged domain repository contracts, conformance and
fault-test gates, a source-preserving migration strategy, and a controlled
cutover/cleanup sequence.

No design blocker prevents Phase 1. Codec selection remains a bounded Phase 1
spike with a versioned interface and is not permission to alter domain or web
contracts. The first development checkpoint is:

1. define the narrow project KV gateway;
2. implement it with `KvToolbox`, delegating native atomic to
   `toolbox.db.atomic()`;
3. prove ordinary, blob, native-atomic, ownership, and lifecycle behavior with
   contract tests;
4. rewire adapters incrementally while preserving existing conformance.

`pdf-content-http` remains queued until durable persistence reaches its cutover
gate. `pdf-content-site` remains queued behind the accepted HTTP contract.
