# Web multi-reference UX implemented

- Markdown and PDF publication now submit explicit primary-plus-alias reference sets. Aliases are optional, removable, may cross owned namespaces, and refer to one logical content item.
- PDF references use a `Downloadable` checkbox backed by presenter-declared delivery capabilities; one-locator inline and attachment publications are both valid.
- Creator publication and reference-management namespace fields select from owned reservations. Creators without a reservation cannot accidentally fall back to guest publication; guest free-text/random controls remain unchanged.
- Management renders and revision-edits complete reference sets. PDF content-only replacement omits endpoint metadata, and duplicate convenience is withheld where it cannot preserve aliases.
- Public and management PDF projections now handle inline-only, attachment-only, preferred-attachment, and mixed reference sets without assuming an inline/download pair.
- Public exploration moved from home to `/site/explore`, with Home/Explore/Manage navigation, breadcrumbs, canonical form/continuation links, and redirects for old query-bearing home URLs.
- README, API documentation, specification, open risks, and changelog were updated; the obsolete UI projection gap was removed.

Validation: `deno task verify` passed 452 tests; `deno task build` passed.
