# Content envelope plus immutable generation chunks

A page's Markdown source and derived HTML can exceed one Deno KV value (64
KiB), so `DenoKvContentRepository` cannot store a `PageRecord` as a single
value the way identities, reservations, and sessions are stored.

Chosen layout, per case-insensitive locator key:

- Envelope at `["iam-pager", "content-pages", "by-locator", <locator_key>]`:
  schema version, publisher-cased locator, content type, delivery meta, ISO
  dates, `data_encoding: "json"`, generation ID, chunk count, and total data
  byte length. Everything except `data`.
- Chunks at `["iam-pager", "content-pages", "chunks", <locator_key>,
  <generation>, <index>]`: the JSON-encoded `data` bytes split into 48 KiB
  `Uint8Array` values, batched writes staying far below the atomic payload
  ceiling.

Generations are immutable: `put` writes a fresh random generation's chunks
first, then flips the envelope with a versionstamp check, deleting the replaced
generation's chunks in the same atomic commit; contention re-reads and retries
the flip only. Readers reassemble the generation referenced by the envelope and
re-read the envelope when chunks are incomplete: a moved versionstamp means a
concurrent flip (retry), an unchanged one means corruption (typed error).
`delete` removes envelope and chunks in one checked atomic commit.

Consequences accepted: stored `data` must be JSON-serializable (the envelope
names its codec so a later schema version can add binary encodings without a
key migration), and a crash between chunk writes and the flip orphans chunks of
a never-referenced generation — invisible to readers, reclaimed by no sweeper
yet.

Composition mirrors sessions: `IAM_PAGER_CONTENT_STORAGE_BACKEND=deno-kv` is
rejected without Deno KV ownership and inherits its path, because a durable
page in a reserved namespace must not outlive the reservation and user that
authorize it. Rejected alternatives: single-value records (caps page size),
chunking without generations (readers can observe half-replaced pages), and a
content-owned database path (splits referentially linked records).
