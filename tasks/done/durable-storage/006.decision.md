# Make sessions the second durable repository slice

Selected `SessionRepository` before `ContentRepository`. Session records are
bounded by the existing lifecycle and fit one Deno KV value, while the current
page record can exceed one value after source and derived output are combined;
content still needs an immutable-generation/chunking decision before an adapter
can honestly preserve atomic create-or-replace.

Durable sessions are a separate opt-in, not an implication of durable ownership,
but they may use Deno KV only when ownership also uses Deno KV. They inherit the
ownership path/default database. This preserves the legitimate durable-ownership
plus restart-invalidated-session deployment while rejecting authenticated
sessions that could survive their application user or drift to another identity
database.
