# First durable ownership slice delivered

Implemented Deno KV adapters for `IdentityRepository` and
`NamespaceRepository`. Identity user/provider creation and namespace
record/owner-index creation use native atomic commits; versioned ISO-date
serialization stays inside each adapter. Identity profile updates use
versionstamp retries so an older observation cannot overwrite newer profile
data.

Added a shared identity conformance suite and ran both memory and Deno KV
implementations through it; the existing namespace conformance suite runs
unchanged against Deno KV. Cross-instance tests prove repository objects hold no
private persistence state. Environment-driven ownership composition selects both
linked repositories together through
`IAM_PAGER_OWNERSHIP_STORAGE_BACKEND=deno-kv`, with optional
`IAM_PAGER_OWNERSHIP_DENO_KV_PATH`; unset remains memory. This avoids durable
namespace claims pointing at user IDs lost on restart.

Retention is now explicit: ownership records have no application expiry or
deletion, backend/path changes do not migrate data, and backup/recovery belongs
to the KV provider or operator. Content and sessions remain process-local.
Verification: `deno task test` passes 229 tests; full check/build gates are
recorded with the implementation commit.

Next: select the next repository by product need. A naive single-value Deno KV
`ContentRepository` adapter cannot be assumed safe because source plus derived
page data may exceed KV value limits; settle chunking/record layout before
choosing it.
