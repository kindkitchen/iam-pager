# Persist ownership identities with reservations

Supersedes the isolation in [[003.decision]]: enabling durable namespace
reservations while identities remain process-local would orphan every claim on
restart, because the same provider subject would receive a new application user
ID. That configuration must not be exposed.

The first coherent vertical slice therefore persists the ownership chain as one
backend choice: application users, external identities, and namespace
reservations share one Deno KV database. Session and content repositories remain
independent and in-memory. The composition root still injects each repository
through its own domain interface; only production backend selection bundles the
referentially dependent stores.
