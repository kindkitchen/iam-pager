# Use strict two-part multipart and single byte ranges

PDF create and revision-bound replacement use `multipart/form-data` on the
existing page endpoints. The request contains exactly `metadata.json` as
`application/json` and one named `application/pdf` file. The complete stream is
bounded to 16 MiB plus 64 KiB, metadata to 16 KiB, and the file to 16 MiB before
the pure PDF command is constructed. Replacement repeats the complete endpoint
set so HTTP cannot convert a one-endpoint content type into an incomplete PDF
publication.

The concrete PDF endpoint policy requires a canonical inline binding and at
least one attachment alternate, all supplied by the publisher. HTTP never
manufactures paths or infers behavior from a suffix.

Direct PDF delivery supports one byte range with strict `206`/`416`, exact
`If-Range`, `If-None-Match`, `Accept-Ranges`, and an opaque strong validator per
page revision. Multiple ranges are rejected. Bounded full `200` remains the
fallback; generic streaming and multipart byte ranges remain later work.
