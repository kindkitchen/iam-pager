# ContentAsset external source - draft design

## Current shape

`lib/content/asset.ts`: `ContentAsset<Data>` = `content_asset_id`,
`content_type`, `data`, `meta: ContentMeta`, `created_at`; immutable once
created; `content_asset_violation` guards structure.
`lib/storage/kv-content-asset-repository.ts` + `content-data-codec.ts`
persist it.

## Proposed shape

```ts
export type ContentAssetSource =
  | { readonly kind: "inline" } // data materialized locally (default)
  | {
    readonly kind: "external";
    readonly ref: ExternalContentRef; // provider_id, connection_id, external_ref, integrity?
  };

export interface ContentAsset<Data = unknown> {
  readonly content_asset_id: ContentAssetId;
  readonly content_type: string;
  readonly source: ContentAssetSource;
  readonly data: Data; // inline: full data; external: bounded descriptor only, never payload bytes
  readonly meta: Readonly<ContentMeta>; // always local: media_type, size_bytes, filename
  readonly created_at: Date;
}
```

Decisions to hold:
- Assets stay immutable; repair after external loss creates a NEW asset (page
  replacement), consistent with the existing "never updated in place" rule.
  The missing-flag therefore lives on page/aggregate state (task
  external-content-delivery-fallback), not on the asset.
- Back-compat by defaulting: decoder maps records lacking `source` to
  `{ kind: "inline" }`. No KV migration pass.
- `content_asset_violation` additions: external requires valid
  `ExternalContentRef` fields (bounded, route-safe provider id); external
  forbids oversized inline `data`.

## Work items

1. Extend `asset.ts` model + violations + tests (`asset` unit tests cover
   both source kinds and the invalid combinations).
2. Extend `content-data-codec.ts` (+ tests) - versioned encoding tolerant of
   legacy records.
3. Extend `kv-content-asset-repository.ts` (+ its conformance/tests) - store
   and roundtrip external assets; assert no payload bytes stored for
   external.
4. Sweep call sites that construct assets (`lib/page/service.ts`,
   `lib/content/md-page.ts`, `pdf.ts`, tests) to pass explicit
   `source: { kind: "inline" }` - no behavior change yet.
5. Docs: specification pages.md asset section; CHANGELOG.

## Acceptance

- Full test suite green with only additive behavior (all existing flows still
  inline).
- An external asset can be created, persisted, and read back with local
  metadata and zero payload bytes in KV.
