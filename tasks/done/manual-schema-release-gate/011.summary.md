# Simplified database releases to explicit manual work

`pre-deploy` is now a platform-compatible `echo` that always succeeds and has no
permissions, scripts, environment reads, database access, build, test, or schema
behavior. Application composition no longer interprets `DENO_TIMELINE`; storage
selection follows the configured repository backends directly in every context.

The old schema-upgrade checker, per-schema state repository, transition claims,
contention runner, guarded writer, remote argument vectors, and deployment
connection composition were removed. The replacement under
`lib/database-schema/` keeps one manifest-store interface, the compatible Deno
KV manifest format/key, pure health inspection, a small adjacent repeat-safe
migration registry, and one final compare-and-set publication.

Manual `db:check` and `db:update` tasks require one explicit local path or Deno
KV connector URL. Remote tokens come only from `DENO_KV_ACCESS_TOKEN`. Their
output explains missing target/token, connection failures, unversioned,
wrong-project, stale, future, unsupported, missing, unknown, malformed, failed
migration, and concurrent publication states. Update derives targets from code,
prints inspection first, and requires `--confirm=iam-pager` before a write.
Registry gaps fail descriptively before a database opens. Record-level runtime
schema validation remains unchanged.

README, CHANGELOG, QT-PREDEPLOY, and OQ-SCHEMA-UPGRADES now describe the manual
responsibility and explicit preview storage configuration. Verification passed:
446 tests, formatting/lint/type checks, production build, the no-op pre-deploy
smoke, and missing-input database-task smoke.
