# Creator management panel implemented

Delivered the DS-PROTECT site management UI strictly as a projection over the
existing contracts.

## What was built

- `lib/ui/page-management.ts` - web-independent logic: the
  `PageManagementPanel` model, `CreatorPageManagementPresenter` over
  `ManagedPageLister` (rows match `/api/pages` summary shape, ETags via
  `format_page_etag`), API response validation
  (`management_summary_from_api`, `managed_md_page_draft`), request
  preparation for list/inspect/PATCH/DELETE (CSRF + `If-Match`, empty patch
  throws), and `format_size_bytes`.
- `lib/ui/page-management.test.ts` - 11 tests over presenter (hidden guest,
  API-shaped rows, continuation cursor) and every preparation/validation
  helper, using a real `PageService` on memory repositories.
- `islands/PageManagementPanel.tsx` - list with load-more continuation,
  inspect-then-edit through the existing `PageEditor` + `ClientPagePreviewer`,
  access toggle, two-step delete; 412 responses surface a conflict notice and
  refresh the affected row; 404 drops the row.
- Composition: `page_management_panel` presenter added to `AppServices`;
  `SiteApp` renders the panel for creators; all three site routes pass it.
- `static/site.css` panel styles; spec updates in `delivery-slices.md`
  (DS-PROTECT), `capabilities.md` (CP-MANAGE), `experiences-and-scope.md`
  (EX-MANAGE); CHANGELOG entry.

## Verification

- `deno task check` and `deno task test` green (356 tests, up from 345).
- `deno task build` bundles the island.
- Composed smoke against the built server with the local Google preset:
  guest home hides the panel; after mock-consent sign-in the panel renders;
  namespace reservation plus managed create show the row server-rendered;
  PATCH access toggle with current ETag returns 200/revision 2; a stale
  validator returns 412; DELETE returns 204 and the row disappears.

## Notes

- Rows reuse the exact API summary field names, so the island refreshes any
  row from any management response without translation.
- Only `md-page` content opens in the editor; other content types degrade to
  a clear message (future content types stay safe by default).
