# Creator management site UI (completes DS-PROTECT)

## Why now

The page-management API core is done (done task `page-management-api`):
create/list/inspect/update/delete with session auth, synchronizer CSRF, opaque
pagination, strong revision ETags, and owner-private direct delivery.
`docs/specification/delivery-slices.md` DS-PROTECT explicitly leaves
"Management UI" as the remaining work of the slice. Finishing the in-flight
slice precedes opening new ones.

## Scope

Authenticated creator, inside the site (`/site`), can:

- see the account's managed pages across reserved namespaces: bounded list
  using the existing opaque pagination, owner-safe fields only;
- inspect a single page: locator, access, revision, timestamps, content source;
- edit content through the existing PageEditor stack and submit via the
  revision-bound PATCH contract (a stale revision surfaces as a clear conflict,
  never a silent downgrade);
- toggle public/private through the same atomic revision-bound PATCH;
- delete with explicit confirmation via revision-bound DELETE;
- reach the direct URL of any managed page.

Presentation state (list position, selection, edit buffer) may live
client-side; every read and mutation goes through the existing HTTP contracts
with session authentication and synchronizer CSRF.

## Non-goals

- rename, duplicate, tags, filters, bulk actions (DS-MANAGE, task
  `management-expansion`);
- public viewing or exploration (tasks `public-view-capability`,
  `public-exploration`);
- new PageService capabilities: if the UI reveals a genuinely missing contract,
  extend the interface in `lib/` first with tests, then project it.

## Acceptance

- The creator flow above works end to end in the composed Fresh app.
- No page read or mutation bypasses the PageService/API contracts.
- Spec updates land in the same change: DS-PROTECT in `delivery-slices.md`,
  CP-MANAGE in `capabilities.md`, EX-MANAGE in `experiences-and-scope.md` mark
  the site management UI delivered.
- CHANGELOG entry; check and the full test suite green.

## Invariants (project conventions to preserve)

- Interface-first: capability contracts live in `lib/` and are satisfied by
  implementations; consumers depend on contracts only.
- Logic is web-independent: behavior lives in `lib/`; Fresh routes, islands,
  and components are one secondary projection of it.
- Specs first: `docs/specification/` (and `docs/api/` when the HTTP surface
  changes) update together with the implementation, never after.
- Deno with import map; std packages and default solutions over libraries.
- Naming: snake_case variables/properties, kebab-case files, CamelCase
  frontend components.
- `CHANGELOG.md` entry with every change; keep README and docs in sync.
- GitButler workspace: use `but` for commits; do not push.
