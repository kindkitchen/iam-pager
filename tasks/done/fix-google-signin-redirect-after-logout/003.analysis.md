# Redirect mismatch is configuration-sensitive, not logout state mutation

Two consecutive original-mode authorization requests from the same composed Google service emit the identical configured `redirect_uri`; logout only revokes the iam-pager bearer and creates a guest session. Google retaining its own login session explains why a repeat attempt may skip account selection.

The active private local configuration emits `http://localhost:5173/auth/google/callback`, and the configured client accepts that URI at Google's authorization endpoint. The reported deployment therefore uses a different client/URI combination or a request-derived original-mode URI. Existing authenticated sessions can mask such deployment drift until logout forces a new OAuth request.

The code currently lets `IAM_PAGER_GOOGLE_AUTH_REQUEST_HOST_PATTERN` override the configured URI even in `original` mode, despite Google requiring every resulting URI to be registered exactly. The robust hotfix direction is to make original mode always use its required configured callback; dynamic request-host callbacks remain local mock-preview behavior.
