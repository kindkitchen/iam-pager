# Hotfix completed

Real Google OAuth now always uses `IAM_PAGER_GOOGLE_AUTH_REDIRECT_URI`. The sign-in request-host pattern is parsed and used only in local mock mode, and the service resolver independently rejects dynamic callbacks in original mode. Local HTTPS previews retain their allowlisted request-derived callbacks.

Regression coverage now verifies stable original-mode authorization URLs across repeated starts and exercises the complete local sign-in, logout, fresh guest rotation, and second sign-in flow with an unchanged callback. README, environment catalog, deployment guide, authentication specification, and changelog document the boundary and explain why Google may skip account selection after app-only logout.

Validation passed: `deno task verify` (671 tests) and `deno task build`. Deployment still must set an exact `IAM_PAGER_GOOGLE_AUTH_REDIRECT_URI` registered under the matching Google sign-in client; application code cannot repair a wrong client/Cloud Console pair.
