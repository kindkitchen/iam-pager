# Restore configurable production startup

## Outcome

The built Fresh server must start successfully with validated local or original
Google authentication configuration. `deno task --env-file=<file> start` must
honor an optional `PORT` value; with no `PORT`, it must retain Deno's native
port-8000 default rather than duplicating that value in application code.

## Root cause to verify

The current SSR bundle keeps gauth presets in dynamic chunks. Those chunks
statically import Effect and gauth symbols from `server-entry.mjs`, while that
entry has a top-level await on `app_services()` which is itself waiting for the
preset chunk. This circular module evaluation leaves the startup promise
unresolved. Port argument placement is a separate issue: task arguments appended
after `_fresh/server.js` become script arguments and cannot configure `deno
serve`.

## Acceptance

- Break the SSR chunk cycle without deferring configuration validation until the
  first request.
- Add an interface-backed parser for optional production server environment.
- `PORT=5173` binds the built server to 5173; missing `PORT` uses Deno's default.
- Invalid ports fail before listening without leaking environment values.
- Build and smoke local and original Google modes without network OAuth calls.
- Update README, specification documentation, and CHANGELOG.
