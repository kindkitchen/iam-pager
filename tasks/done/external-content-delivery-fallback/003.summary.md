# External delivery and fallback implemented

External assets now resolve through the configured provider registry for direct and site-wrapper delivery. Complete provider bytes are bounded by local size, verified against local size and SHA-256 facts, and served with local media type, filename, endpoint profile, and access policy.

Missing content, revoked connections, integrity mismatches, unregistered providers, and transient provider failures produce one platform-owned HTML fallback. Direct delivery returns `503`, `no-store`, safe isolation headers, and a bounded provider retry hint when available. The wrapped site view returns its own `503` unavailable state without exposing provider details.

Page aggregates now carry optional `external_missing` health with safe cause and detection time. Memory and Deno KV repositories implement an asset-bound, revision-neutral, idempotent health update interface. Definitive failures record health, transient failures do not, and verified recovery clears it. Health persistence failure does not replace verified visitor content or fallback behavior with an application error.

Google Drive reports `connection_revoked` separately from missing objects. Application composition supplies the provider registry to `PageService`. Public list/exploration summaries materialize external metadata without fetching provider bytes.

Documentation was updated in `README.md`, `docs/specification/external-storage.md`, and `CHANGELOG.md`. Verification: `deno task check` passed and the complete `deno task test` suite passed with 649 tests.
