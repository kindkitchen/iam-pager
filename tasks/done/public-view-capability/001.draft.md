# Public view capability and thin site wrapper (DS-VIEW)

## Why after creator-management-ui

DS-PROTECT closes first. This task then introduces the first visitor-facing
site surface and the public-listing primitive that `public-exploration` builds
on.

## Scope

Logic first (`lib/`, interface-first, no Fresh imports):

- a public-view contract exposing: resolve an eligible public page for wrapped
  viewing by locator; list a creator's public pages (bounded, pagination
  consistent with the existing cursor model); resolve the namespace default
  page when one exists;
- exclusions are part of the contract: private pages and guest (unreserved)
  pages never appear in listings; a private page behaves as missing
  (OQ-ACCESS);
- served from the existing PageService/PageRepository data; extend the
  interfaces in `lib/page` only where visibility-scoped listing genuinely
  requires it, with conformance coverage for memory and Deno KV.

Web second (`routes/site/...`):

- thin wrapper view for a public page: content preview when the format permits
  (existing supported formats), suitable fallback otherwise;
- links: direct content URL, creator default page, creator's other public
  pages;
- creator content stays visually and technically distinguishable from platform
  controls (EX-VIEW); no creator markup executes inside the site's trust
  boundary (OQ-ISOLATION);
- missing or private wrapped views produce a real missing response
  (OQ-MISSING).

## Non-goals

- search or cross-namespace browsing (`public-exploration`);
- tags (`management-expansion`);
- view counters or popularity.

## Acceptance

- Contract and implementations tested web-independently; wrapper routes are
  thin projections.
- Spec updates in the same change: DS-VIEW in `delivery-slices.md`, CP-VIEW in
  `capabilities.md`, EX-VIEW in `experiences-and-scope.md`.
- CHANGELOG entry; check and the full test suite green.

## Invariants (project conventions to preserve)

- Interface-first: capability contracts live in `lib/` and are satisfied by
  implementations; consumers depend on contracts only.
- Logic is web-independent: behavior lives in `lib/`; Fresh routes, islands,
  and components are one secondary projection of it.
- Specs first: `docs/specification/` (and `docs/api/` when the HTTP surface
  changes) update together with the implementation, never after.
- Deno with import map; std packages and default solutions over libraries.
- Naming: snake_case variables/properties, kebab-case files, CamelCase
  frontend components.
- `CHANGELOG.md` entry with every change; keep README and docs in sync.
- GitButler workspace: use `but` for commits; do not push.
