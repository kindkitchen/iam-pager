# Durable Deno KV persistence landed (plan link 3)

Added conforming durable persistence for API keys:

- `lib/api-key/repository-conformance.ts`: one shared `ApiKeyRepository`
  conformance suite (missing lookups, roundtrips, ID/hash collision refusal,
  concurrent same-hash creates, clone safety, owner-scoped listing, update
  owner/revision rules with a single concurrent winner, revision-bound revoke
  freeing identifiers, revoke-all isolation and repetition, identifier reuse
  after revoke-all). `MemoryApiKeyRepository` tests are now this suite.
- `lib/api-key/kv-repository.ts`: `DenoKvApiKeyRepository` over the project
  `KvRecordGateway`. Create commits record + secret-hash index + owner index
  in one native atomic operation; update/revoke are versionstamp-checked.
  Revoke-all is a single owner-generation bump — one linearizable commit that
  invalidates unbounded key counts instantly; dead entries are purged lazily
  by later operations (including create, so identifiers stay reusable).
  Stored records are validated exactly and fail closed on malformed data;
  only hashes and bounded metadata are persisted.
- `lib/storage/api-key-storage.ts`: `IAM_PAGER_API_KEY_STORAGE_BACKEND`
  selector via `parse_dependent_storage_config` (durable keys require durable
  ownership and inherit its KV path) plus `DefaultApiKeyRepositoryFactory`;
  wired through `create_configured_app_services` with a factory override
  option. Composition test proves the selection travels with the others.
- Docs: README persistence section, QT-STORAGE specification, CHANGELOG.

Gates: `deno task check` and `deno task test` pass (529 tests).
