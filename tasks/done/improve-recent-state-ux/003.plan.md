# UI-only implementation plan

1. Put random-name generation and CSS preset declarations in UI-support modules
   behind interfaces/data contracts.
2. Keep the guest form as the API adapter and extract a Page editor component
   for Markdown, CSS, and preview presentation.
3. Reuse `MdPageHandler` for preview derivation/rendering instead of creating
   browser-owned Markdown logic.
4. Make layout rules mobile-first, enhance at wider breakpoints, then run
   format, lint, type, tests, and production build.
5. Review for boundary leaks, accessibility, preview isolation, and unchanged
   publish payload semantics before moving to done.
