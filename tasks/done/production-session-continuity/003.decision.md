# Treat the incident as deployment configuration

The production cookie was valid and sent back by the client, but the deployed application intermittently replaced the same unexpired bearer with a fresh guest credential. That is the defined result when a repository cannot find the bearer. The configured composition independently defaults ownership, sessions, and pages to process-local memory; attaching a Deno KV database does not select those adapters.

Existing tests remain valid: they prove each repository contract, explicit Deno KV composition, and the authentication lifecycle within shared storage. Configuration tests deliberately assert that unset backends select memory. They do not prove that an external deployment selected durable storage.

Document rather than change runtime semantics. Production must attach its database and explicitly set all three backend variables to `deno-kv`. Local development may retain the unset memory defaults. A serverless preview may explicitly use memory only with the expectation that authentication and content can disappear between requests; any preview requiring continuity must also use shared storage.
