# Delivered step 2; status: active -> done

## What landed

- `lib/namespace/service.ts` — `NamespaceReservationService` implementing the
  new `NamespaceReservationManager` contract (`lib/namespace/interfaces.ts`):
  `reserve` validates the namespace-only locator through the locator engine
  (typed `invalid_namespace` and `forbidden_namespace` rejections, so
  reservation validity can never diverge from publishing/lookup validity),
  then delegates to `NamespaceRepository.reserve` (`taken` on loss);
  `list_owned` returns a user's reservations. Typed results, no string
  parsing for the future API layer.
- `lib/publishing/interfaces.ts` — `PublishActor` (`guest` | `user`),
  optional `PublishRequest.actor` (absent = guest, so an unstated actor never
  gains rights), `PublishResult` reason `namespace_reserved`, and the
  `PublishingAuthorizer` contract.
- `lib/publishing/namespace-authorizer.ts` — `NamespacePublishingAuthorizer`
  implementing the DA-NAMESPACE table over `NamespaceRepository`: unreserved
  allows everyone; reserved allows only the owner (case-insensitive via the
  repository contract).
- `lib/publishing/service.ts` — `PublishingService` consults an optional
  authorizer after locator validation and before content handling;
  `ContentRepository` stays protection-free by contract. Absent authorizer
  keeps the pre-reservation world (composition root always wires one).
- `lib/publishing/guest-http.ts` — guest API passes an explicit guest actor
  and maps `namespace_reserved` to 403.
- `lib/app.ts` — composition root wires `MemoryNamespaceRepository`,
  `NamespaceReservationService`, and the authorizer; exposes
  `namespace_repository` and `namespaces` in `AppServices`.
