# Storage connection model implemented

Added strict owner-safe `StorageConnection` metadata and separate server-only
credentials under `lib/external-storage/`. `StorageConnectionRepository` now
supports create, lookup, stable owner listing, one active connection per
(user_id, provider_id), same-provider-subject reauthorization, idempotent
owner-scoped revocation, and provider-only credential get/put.

Both `MemoryStorageConnectionRepository` and
`DenoKvStorageConnectionRepository` pass one shared conformance suite. Revoked
metadata is retained while token material is destroyed; reauthorization can
restore the same record only when its active slot is free. The memory adapter
supports one-shot fault injection.

`AesGcmStorageCredentialCipher` uses randomized AES-256-GCM with the connection
ID as authenticated additional data. Deno KV stores credential ciphertext under
separate keys, validates stored metadata strictly, and uses native atomic
operations for active uniqueness, reauthorization, and revocation. The external
key is canonical base64url configuration named
`IAM_PAGER_STORAGE_TOKEN_KEY`.

README, CHANGELOG, and external-storage/capability/verification specifications
were updated. Verification passed: `deno task check` and the complete 607-test
`deno task test` suite.
