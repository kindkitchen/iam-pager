# Provider interface family - draft design

## Pattern to mirror

`lib/auth/interfaces.ts` + `lib/auth/strategy-registry.ts`: routes and
services depend on the contract and a read-only resolver; providers register
at composition time. Conformance style:
`lib/auth/identity-repository-conformance.ts`.

## Proposed contract (to refine during implementation)

```ts
// lib/external-storage/model.ts
export interface ExternalContentRef {
  readonly provider_id: string; // e.g. "google-drive"
  readonly connection_id: string; // local storage-connection id
  readonly external_ref: string; // provider-native file reference
  readonly integrity?: string; // checksum/etag captured at link time
}

export type ExternalStorageFailure =
  | { readonly ok: false; readonly reason: "external_content_missing" }
  | { readonly ok: false; readonly reason: "external_source_unreachable" }
  | { readonly ok: false; readonly reason: "connection_revoked" }
  | { readonly ok: false; readonly reason: "provider_error"; readonly detail: string };

// lib/external-storage/interfaces.ts
export interface ExternalStorageProvider {
  readonly provider_id: string;
  readonly capabilities: readonly ExternalStorageCapability[]; // "read" | "write" | "delete" | "stat"
  fetch_content(ref: ExternalContentRef): Promise<ExternalStorageResult<ExternalContentPayload>>;
  stat_content(ref: ExternalContentRef): Promise<ExternalStorageResult<ExternalContentStat>>;
  put_content?(input: ExternalContentPutInput): Promise<ExternalStorageResult<ExternalContentRef>>;
  delete_content?(ref: ExternalContentRef): Promise<ExternalStorageResult<void>>;
}

export interface ExternalStorageProviderResolver {
  resolve(provider_id: string): ExternalStorageProvider | null;
}
```

Notes:
- `read` + `stat` mandatory; `write`/`delete` optional capabilities so a
  read-only provider (public GitHub repo) still satisfies the interface.
- Failure taxonomy is the load-bearing part: `external_content_missing` must
  be unambiguous because it triggers the owner-warning/fallback path, while
  `external_source_unreachable` must never mark content missing.
- Providers receive tokens/credentials via their own composition, not through
  the interface - keeps the contract provider-agnostic.
