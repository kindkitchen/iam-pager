# Add provider-neutral identity and strategy boundaries

Started phase 2 with `IdentityRepository`, provider-neutral
`AuthenticationStrategy`/resolver contracts, atomic `MemoryIdentityRepository`,
and the default multi-strategy registry. External identities are unique only by
`(strategy_id, provider_subject)`; mutable email/name/picture observations
update without cross-strategy email linking or stale profile rollback. Strategy
IDs are lowercase and route-safe, duplicate registration fails at composition,
and unknown strategies resolve cleanly for a future `404` adapter.

Wired the empty provider registry and process-local identity repository in the
composition root. Added ten focused identity, concurrency, non-linking,
registry, and composition tests; all 131 tests and checks pass. Next is bounded,
session-owned OAuth attempts plus authentication orchestration before HTTP
routes.
