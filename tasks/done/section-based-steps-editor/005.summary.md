# Section-based Steps editor delivered

The old physical-line adapter became the `MarkdownSectionEditor` interface and
deterministic implementation. It groups complete and unterminated fenced code
blocks losslessly, exposes language plus multiline body drafts, prevents lossy
multiline-to-line type changes, and chooses a longer backtick fence when body
content could close the default fence. Reordering moves the whole raw section.

The Steps UI now consistently says section. Code block is available when adding
or changing safe content, with newline-preserving Code Paste/Copy/Clear actions.
List UI is reduced to `Is list item`; enabling it reveals an indented `Numbered`
checkbox, where unchecked means bulleted. Code blocks stay standalone because
list-owned fenced blocks require coordinated indentation across every line.

Up, Down, Above, and Below controls were removed. New sections append at the end
and can be moved from a six-dot grip. Custom Pointer Event ordering supports
mouse, touch, and pen, highlights before-section and final drop positions, and
assists edge scrolling. Arrow, Home, and End keys on a focused grip provide the
non-pointer path with live announcements.

Verification passed with `deno task check`, all 92 tests, production build,
scripted Chromium code/list checks, real mouse and emulated touch final-position
drags, keyboard ordering, and mobile visual inspection.
