# Boundaries and implicit issues

A code block cannot be represented safely as the old one-line draft: its fence,
optional language, body, and closing fence form one ordered multi-line unit.
Steps therefore needs a section parser whose raw value may span physical lines.
To avoid becoming an incomplete Markdown AST, the first grouped construct will
be a fenced code block; all other safe focused forms remain one-line sections
and unfamiliar source remains raw.

Dragging must move the complete section, so a code block can never be split by
reordering. Creation can be append-only once visible Above/Below buttons are
removed: the user adds a section and drags it to a drop position. Explicit
before-section and final drop indicators make the destination model visible.

Native HTML drag-and-drop is unreliable in a mobile-first editor. Use Pointer
Events on a dedicated grip for mouse/touch/pen, plus focusable grip keyboard
ordering and live announcements. This keeps the requested compact UI without
removing the non-pointer path.

List checkboxes apply to focused single-line content. Fenced code blocks remain
standalone because a Markdown list-owned fence requires coordinated indentation
of every body and fence line, which is outside this safe first section slice.
