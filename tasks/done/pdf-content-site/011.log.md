# Typed failures and creator PDF management landed

Completed the next two ordered site steps. Added a web-independent page API
failure presenter that distinguishes endpoint, PDF, request-size, authority,
stale-revision, deployment-availability, and generic request outcomes while
discarding unknown response detail. Publishing consumes this model and retains
its existing draft and selected-file state.

Creator management now derives PDF preview and download actions only from
server-returned endpoint profiles. Owner inspection validates and renders the
bounded filename, media type, size, PDF version, and replace capability without
holding bytes. Replacement keeps the selected file on failure, repeats the
complete current endpoint set, and sends one multipart PATCH bound to creator
CSRF and the exact visible ETag. A stale response refreshes the row and PDF
metadata but is never retried silently. Markdown editing remains on its existing
JSON path, and unsupported endpoint-aware PDF duplication is not offered.

Added presenter, response-boundary, metadata, multipart decoder round-trip, and
component coverage. All 577 tests, `deno task check`, and `deno task build` pass.
Next is the public browser-native PDF wrapper with direct preview/download
fallbacks.
