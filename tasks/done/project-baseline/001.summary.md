# Project baseline

The authoritative requirements are `README.md`, `docs/specification/`, and
`docs/api/pages.md`. This is the complete task-level state; there are no open
tasks or retained delivery histories.

## Product

`iam-pager` publishes Markdown or PDF content at deterministic namespace and
optional page-name locators. Direct paths return content. The site is a separate
projection for publishing, wrapped viewing, public exploration, namespace
reservation, and creator management; product rules remain in `lib/`.

Guests may publish public, undiscoverable trials in unreserved namespaces.
Google-authenticated creators reserve namespaces and perform exact-revision
managed mutations. Missing, private, invalid, and unauthorized visitor reads
remain non-disclosing. The platform assigns no meaning or relationships to
pages.

A logical page has one stable management ID, immutable current asset, access,
tags, revision, management/public projections, and one canonical plus up to
seven explicit delivery endpoints. Every endpoint selects `inline` or
`attachment`; paths and filenames do not imply behavior. Markdown stores source,
sanitized HTML, and optional CSS. PDF stores structurally screened detached bytes
and supports byte-identical preview/download endpoints, validators, and one byte
range.

## Interfaces and web boundary

The central contracts are:

- `LocatorEngine` for transport-independent locator validation and formatting;
- `PageService` for publication, authority, lifecycle, delivery, and queries;
- `PageAggregateRepository` for assets, pages, endpoint claims, and projections;
- focused identity, namespace, session, authentication, content-handler,
  presenter, and HTTP interfaces.

Memory and Deno KV implementations satisfy the same repository conformance
suites. Presenters return complete bounded view models. Components render those
models and prepare requests without deciding authority or persistence. Fresh
routes resolve request context, select an adapter operation, and map its result;
they contain no product rules.

An implementation remains valid when it satisfies a current interface, even if
one composition does not select it.

## Persistence and security

Deno KV stores strict identity, namespace, session, aggregate, endpoint,
projection, and manifest-backed content records. Content is staged, hashed, and
verified before publication. Page visibility changes use one native atomic
commit. Corrupt or incoherent records fail closed. Durable sessions and pages
require durable ownership and share its KV path.

Every routed request receives a typed guest/authenticated session and server
request ID. Bearers, OAuth state, and CSRF values are bounded; persisted bearer
and state lookup values are hashes. Authentication consumes one-use attempts,
rotates credentials, and never exposes provider tokens or failures. Logout
revokes authenticated access and creates an unrelated guest session.

Fresh-independent HTTP adapters enforce bounded strict JSON/multipart shapes,
CSRF, strong revision ETags, request limits, no-store policy, content isolation,
explicit disposition, and PDF validator/range semantics. Direct active content
never receives the platform shell. Wrapped Markdown is sandboxed and
no-referrer; PDF uses the browser-native viewer with explicit direct and download
links.

## Site and verification

The mobile-first site includes guest/creator publishing, namespace reservation,
creator page management, public exploration, and wrapped views. Markdown keeps
raw source authoritative while supporting Raw/Steps editing, lossless fenced
blocks, ordering/merge controls, CSS, draft preview, adaptable layout, and
fullscreen preview. PDF publishing and replacement use bounded file-selection
helpers and explicit endpoint intent. Stale mutations refresh state without
silent retry.

Shared conformance covers memory and Deno KV page, namespace, identity, and
session repositories. The focused suite protects current locator, authority,
session, page lifecycle, endpoint, asset, query privacy, strict HTTP, PDF
byte/range, presenter, component, corruption, and concurrency behavior.
`deno task verify` and the production Fresh build pass at this baseline.

## Deliberate open scope

Not implemented: quotas, publishing rate limits, guest expiry, account deletion,
backup/retention guarantees, orphan sweeping, full-text/relevance indexes,
generic or active content, PDF text extraction/PDF.js, or external storage.
Memory storage is process-local; durable deployments must select Deno KV.
Local fake authentication must remain loopback-only or on a narrow designated
preview host. PDF validation is structural screening, not malware certification.
