# Current project baseline

The authoritative requirements are `README.md`, `docs/specification/`, and
`docs/api/pages.md`. This is the task-level current-state summary; there are no
open tasks.

## Product and boundaries

`iam-pager` publishes Markdown or PDF content at a deterministic namespace and
optional page-name locator. Direct paths return content. The site is a separate
projection for publishing, wrapped viewing, exploration, namespace reservation,
and creator management; product rules remain in `lib/`.

A page has one stable management ID, immutable current asset, revision, access,
tags, management/public projections, and one canonical plus up to seven
explicit delivery endpoints. Guests may publish public undiscoverable trials in
unreserved namespaces. Google-authenticated creators reserve namespaces and
perform exact-revision managed mutations. Missing, private, invalid, and
unauthorized visitor reads remain non-disclosing.

The central contracts are `LocatorEngine`, `PageService`,
`PageAggregateRepository`, focused identity/namespace/session/authentication
interfaces, content handlers, presenters, and Fresh-independent HTTP adapters.
Memory and Deno KV remain valid implementations of the same repository
interfaces; no implementation disconnected from a current contract remains.

## Current persistence and web composition

Deno KV stores only the current identity, namespace, session, page aggregate,
projection, endpoint-claim, and manifest-backed content formats. Records use
native values and strict shared validation without schema-version aliases or
migration branches. Page visibility still commits atomically; content is staged,
hashed, verified, and published before a page can reference it. Durable session
and page selection still requires durable ownership and a shared KV path.

Opaque cursors share one strict codec and bind their complete normalized query
scope. Shared helpers own canonical base64url, exact storage-record validation,
strict HTTP objects, storage selection, and repository query semantics. Routes
remain thin; `/` and `/site` share one site projection.

Authentication preserves logical sessions while rotating hashed bearer
credentials, consumes bounded one-use attempts, and uses CSRF-bound logout.
HTTP adapters retain strict JSON/multipart bounds, ETags, CSRF, no-store policy,
isolation, explicit disposition, and PDF validator/range behavior. Components
render presenter models and prepare requests without owning authority or
persistence logic.

## Verification and deliberate scope

The focused suite contains 442 tests. Shared conformance still runs against both
memory and Deno KV repositories, while composition tests now verify wiring
instead of repeating lower-layer behavior. `deno task verify` and the production
Fresh build pass.

Still outside scope: quotas, publishing rate limits, guest expiry, account
deletion, backup/retention guarantees, orphan sweeping, full-text/relevance
indexes, generic or active content, PDF text extraction/PDF.js, external storage,
and automatic migration or rollback. Storage has one current format; changing it
requires an explicit deployment decision once retained data matters.
