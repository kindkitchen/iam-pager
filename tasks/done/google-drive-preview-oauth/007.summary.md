# Local Drive now inherits the auth preview-host policy

The deployment failure occurred because Drive local mode had no `IAM_PAGER_GOOGLE_DRIVE_REQUEST_HOST_PATTERN`, so parsing fell through to the static callback/mock-consent pair and required `IAM_PAGER_GOOGLE_DRIVE_MOCK_CONSENT_URL`.

Configured app composition now passes Google auth's already validated request-host pattern as a local-only Drive fallback. Precedence is: a Drive-specific pattern, a complete static Drive callback/mock-consent pair, then the inherited auth pattern. Original Drive mode never inherits it. Partial stale static configuration no longer prevents dynamic preview composition.

Regression coverage reproduces the missing mock-consent variable with an auth pattern, verifies Drive-specific override and complete-static precedence, and runs the full request-derived consent flow with no Drive pattern or credentials. Environment and deployment documentation now requires only the auth pattern for the common preview profile and describes the optional Drive override.

Validation passed: `deno task verify` (667 tests) and `deno task build`.
