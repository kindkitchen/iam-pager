# Public exploration, first version (DS-EXPLORE)

## Decision to record on start

OQ-EXPLORE: the first exploration version covers page names and author
namespaces only. Tags join when `management-expansion` delivers them;
text-content search and view-count sorting stay out of the MVP. Record this
settlement in `open-questions-and-risks.md` when implementation starts.

## Scope

Logic first (`lib/`, interface-first):

- an exploration contract: browse public pages (bounded, paginated) and search
  by page name and namespace, together or separately;
- exclusion rules are contract-level and conformance-tested: private pages and
  guest pages never enter results (CP-EXPLORE, EX-EXPLORE);
- implementations over the existing repositories for memory and Deno KV; keep
  the contract indifferent to a future index so text-content search can join
  later without changing page URLs.

Web second:

- site browse/search surface; each result leads to the DS-VIEW wrapped page,
  direct content, the creator default page, and the creator's other public
  pages.

## Non-goals

- tags, text-content search, view counts, relevance ranking;
- any exposure of private or guest pages.

## Acceptance

- Contract and conformance tests green on memory and Deno KV; the web layer is
  a thin projection.
- Spec updates in the same change: DS-EXPLORE in `delivery-slices.md`,
  CP-EXPLORE in `capabilities.md`, EX-EXPLORE in `experiences-and-scope.md`,
  and the OQ-EXPLORE settlement in `open-questions-and-risks.md`.
- CHANGELOG entry; check and the full test suite green.

## Invariants (project conventions to preserve)

- Interface-first: capability contracts live in `lib/` and are satisfied by
  implementations; consumers depend on contracts only.
- Logic is web-independent: behavior lives in `lib/`; Fresh routes, islands,
  and components are one secondary projection of it.
- Specs first: `docs/specification/` (and `docs/api/` when the HTTP surface
  changes) update together with the implementation, never after.
- Deno with import map; std packages and default solutions over libraries.
- Naming: snake_case variables/properties, kebab-case files, CamelCase
  frontend components.
- `CHANGELOG.md` entry with every change; keep README and docs in sync.
- GitButler workspace: use `but` for commits; do not push.
