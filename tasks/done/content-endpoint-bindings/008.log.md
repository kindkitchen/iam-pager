# Compose current Markdown behavior through the split model

`PageService` now detects and uses focused content-asset/page-aggregate
capabilities for process-local persistence while retaining the old
`PageRepository` path for the raw-Deno-KV adapter until its planned replacement.
Validated `md-page` content is staged under a fresh immutable asset ID before
page visibility; creates and content updates select that asset, access/tag
changes retain the current asset, duplication shares it, rename replaces the
complete endpoint set, and direct lookup resolves an endpoint before content is
read. The current HTTP/JSON behavior remains one canonical inline endpoint.

Added managed/public aggregate query capabilities with canonical-locator sorting
and cursor filtering, so alternate endpoints cannot become extra management or
exploration rows. `MemoryPageRepository` is now a compatibility projection over
`MemoryPageAggregateRepository`, keeping the old repository conformance as well
as the focused aggregate contract. Aggregate conformance now covers one-row
query cardinality, and service tests inspect immutable asset/reference behavior
plus the retained legacy path.

Next: expose explicit safe endpoint links in owner/public projections and direct
delivery while preserving the compatible JSON shapes where required. The
raw-Deno-KV adapter remains deliberately legacy until the Kvdex persistence
task supplies compatibility or migration.
