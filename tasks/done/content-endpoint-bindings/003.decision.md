# Endpoint locators are explicit publisher configuration

The `example` / `example.pdf` pair is illustrative only. `.pdf` has no reserved,
generated, inferred, or otherwise special meaning.

The required generic capability is:

- one immutable content asset may be referenced through multiple ordinary
  locators;
- the publisher supplies each locator;
- each endpoint binding independently stores its delivery profile, such as
  inline browser display or attachment download;
- all locators use the existing locator validation, authority, and collision
  rules;
- endpoint-set mutation is revision-bound and all-or-none;
- content types declare supported delivery profiles but never generate paths.

This supersedes the automatic PDF alias and suffix edge-table assumptions in
[[001.draft]]. The active specification gate is now endpoint-set cardinality,
canonical designation, profile compatibility, add/change/remove semantics,
namespace scope, and atomic conflicts.
