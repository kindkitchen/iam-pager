# Use non-empty locator references with explicit delivery profiles

The logical page/content identity and immutable asset remain independent from public locators. Every publication has one structurally preferred reference only for management, exploration, and sorting, plus zero or more additional references. There is no domain endpoint-count or same-namespace rule; application authority is checked for every referenced namespace.

Every reference stores a bounded lowercase delivery-profile identifier. A content handler declares its supported subset. `inline` and `attachment` remain the profiles implemented by the current HTTP transport; an unknown future transport profile fails explicitly rather than being treated as attachment.

PDF uses exactly the same reference rules as Markdown and may have one inline or attachment locator or any supported combination. Content-only replacement preserves references. JSON create/update and multipart metadata share the endpoint-set decoder, and duplication may provide explicit destination references.

Deno KV's eight-reference atomic capacity remains an adapter limit returned as `endpoint_capacity_exceeded`, not a content validity rule. The memory reference accepts larger request-bounded sets. The existing site still imposes the former PDF and eight-row assumptions and is intentionally deferred.
