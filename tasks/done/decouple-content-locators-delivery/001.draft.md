# Decouple content, locators, and delivery

A published content item is independent of every URL that references it. Creation requires at least one valid locator; additional locators may reference the same logical content and current immutable asset. A locator reference carries an explicit delivery mode such as `inline` or `attachment`, and the selected content handler decides which modes it supports.

Remove format-specific locator cardinality rules, especially PDF's required inline canonical plus attachment alternate and the domain-level one-to-eight wording. Retain a preferred locator only where a stable management or exploration link is required; it must not become content identity.

Scope covers raw domain/application logic, persistence contracts, HTTP API, tests, and documentation. UI implementation is excluded, but the task must identify UI assumptions that reject or misrepresent API-valid locator/delivery combinations.
