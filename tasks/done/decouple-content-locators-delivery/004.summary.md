# Content/locator/delivery refactor complete

Logical content and immutable assets are independent from their non-empty locator-reference set. One reference remains structurally preferred only for management, exploration, sorting, and stable links; additional references may span namespaces when the actor has authority over each one.

Delivery profiles are bounded extensible identifiers stored on references and checked against each content handler. Markdown remains inline-only; PDF supports inline and attachment without any PDF-specific reference count or required pairing. The current HTTP transport returns 501 for a future profile it does not implement rather than guessing.

The shared API decoder now accepts explicit endpoint sets for JSON and multipart content. Content-only PDF replacement preserves references, JSON PATCH can replace them, and duplicate can receive explicit destination references. Deno KV exposes its eight-reference atomic capacity through `endpoint_capacity_exceeded`; the domain and memory repository have no count rule.

UI code was intentionally unchanged. Its former eight-row, same-namespace, PDF inline-plus-attachment, implicit Markdown, replacement, presenter, and error assumptions are recorded in `docs/specification/open-scope-and-risks.md`.

Verification passed: `deno task check`, all 448 tests, and `deno task build`.
