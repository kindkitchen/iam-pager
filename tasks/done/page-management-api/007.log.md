# Plan step 6 delivered: Deno KV PageRepository

Implemented the durable page adapter from [[003.plan]] in the fresh
`["iam-pager", "pages", ...]` keyspace:

- `DenoKvPageRepository` stores one authoritative schema-versioned envelope by
  stable page ID, a case-normalized locator index, a logically ordered managed
  owner index, and immutable content-generation chunks.
- Trial create/replace, managed create over absent/trial locators, revision-bound
  replace, and revision-bound delete use native conditional atomic commits to
  keep ID, locator, owner, revision, access, metadata, and visible generation
  coherent across repository instances.
- Content chunks are written before visibility. Access-only updates retain the
  exact generation; content replacement atomically flips generations and removes
  the previous chunks. Failed conditions clean unreferenced new chunks
  best-effort, with bounded contention retries.
- A tagged JSON codec preserves plain structured data and `Uint8Array` while
  rejecting unsupported or oversized values before visibility. Reads fail
  closed on unknown schema, malformed envelopes/indexes, impossible
  stewardship/access, mismatched identities/revisions, or incomplete chunks.
- The unchanged 27-test repository conformance now passes against memory and
  Deno KV. Seven adapter tests cover cross-instance persistence, physical
  keyspace/index/chunk layout, access-only generation reuse, content generation
  replacement, complete deletion, pre-visibility codec rejection, and stable
  corruption detection.

README and specification current-state sections now distinguish the implemented
adapter from the still-active legacy route/storage composition. Check, build,
and all 393 tests pass (34 new tests).
