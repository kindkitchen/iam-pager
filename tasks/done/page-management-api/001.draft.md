# Deliver API-first core page management

## Specification basis

This task implements already-designed behavior rather than reopening it:

- `DS-PROTECT`: create, inspect, update, choose public/private, and delete pages
  in a protected namespace;
- `CP-MANAGE`: list and inspect managed pages, update content and metadata, and
  expose the same behavior programmatically;
- `DA-PAGE` / `DA-ACCESS` / `DA-LIFECYCLE`: locator-bound current content,
  owner-only private access, conflict-safe protected mutations, and explicit
  deletion;
- `EX-MANAGE`: authenticated namespace authority and creator control;
- `QT-BOUNDARIES` / `QT-API` / `QT-AUTHORITY`: application logic independent
  from Fresh/UI, shared rules across representations, useful typed errors, and
  server-derived authority.

## Outcome

Provide an interface-first page application layer and explicit HTTP API that
allows an authenticated namespace owner to:

- create a managed default or named page, replacing trial content but never
  silently replacing another managed page;
- list managed pages, optionally limited to one owned namespace;
- inspect editable source and delivery metadata without exposing stored derived
  internals;
- update content and/or public/private access atomically;
- delete a page explicitly;
- retrieve private raw content only through the owner session.

Guest publishing remains a deliberately weak trial mode: public only,
replaceable by other trial writes while unreserved, blocked by reservations, and
never allowed to replace a managed page. Rejected writes leave client-side draft
state untouched.

## Architectural direction

Management identity uses an opaque stable page ID while the deterministic direct
locator remains the public content address. A revision/ETag makes update and
delete preconditions explicit. Storage records distinguish trial from managed
creator pages, allowing the page repository itself to enforce atomic
trial-versus-managed replacement conditions without making web UI or HTTP routes
the source of policy.

## Exclusions

Do not add management UI, rename, duplicate, bulk operations, tags, date/view
filters, exploration/search, namespace release/transfer, external storage,
revision history, share tokens, collaborators, general API bearer tokens, or
legacy data migration. These are later slices; the API/resource model must not
block them.
