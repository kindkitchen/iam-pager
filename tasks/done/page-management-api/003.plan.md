# API-first page management implementation plan

## 1. Delivery boundary

Complete the core DS-PROTECT page-management behavior through raw application
contracts and HTTP APIs. Acceptance is based on service, repository, HTTP, and
direct-delivery behavior; no management UI is required.

In scope:

- public trial page create-or-replace for guest sessions;
- authenticated managed-page creation in an owned reserved namespace;
- managed creation replacing trial content at the same locator;
- bounded owner page listing, optionally filtered by namespace;
- owner source/metadata inspection;
- revision-bound content and/or access update;
- revision-bound deletion;
- public direct delivery and owner-only private direct delivery;
- memory and Deno KV implementations of the same repository contract;
- minimal adaptation of the existing publish form to the new API contract;
- complete API and behavior documentation.

Explicitly later:

- rename, duplicate, bulk delete/access, tags, date/view filters, search;
- management UI, source loading into the editor, or an access selector;
- namespace release/transfer, collaborators, private share links;
- API bearer/token authentication separate from the existing browser session;
- data migration, revision history, or old-URL redirects.

## 2. Domain model

Create `lib/page/` as the page/resource boundary. Keep content-format behavior in
`lib/content/`; stop making content storage itself represent the whole page.

### 2.1 Page identity and authority

Define in `lib/page/model.ts`:

```ts
export type PageId = string;
export type PageAccess = "public" | "private";

export type PageStewardship =
  | { readonly kind: "trial" }
  | { readonly kind: "managed"; readonly owner_user_id: string };
```

A `PageRecord<Data>` contains:

- `page_id`: opaque stable management identity;
- `locator`: publisher-cased namespace and optional page name;
- `stewardship`: trial or server-owned creator identity;
- `access`: public/private;
- `revision`: positive safe integer, starting at 1;
- `content`: content type, stored source/derivation, and delivery metadata;
- `created_at`: page creation time;
- `updated_at`: last successful content/access mutation time.

Move timestamps out of `ContentRecord`: access-only mutation updates the page but
not a fictional content-owned lifecycle. Keep content metadata (`media_type`,
`size_bytes`, optional filename) next to content data.

Enforce application invariants:

- trial implies public;
- private implies managed;
- managed owner IDs are non-empty and generated/resolved server-side;
- page IDs are non-empty route-safe opaque values;
- revisions are positive safe integers;
- locator identity remains case-insensitive while displayed casing is retained.

Do not expose `owner_user_id` in any wire response.

### 2.2 Actor and namespace authority

Generalize `PublishActor` to HTTP-independent `PageActor`:

```ts
{ kind: "guest" } | { kind: "user"; user_id: string }
```

Replace the write-only `PublishingAuthorizer` with a namespace-authority
interface that resolves one of:

- `unreserved`;
- `owned` for the actor;
- `reserved_by_other`.

Its implementation continues to use `NamespaceRepository`; the web layer never
accepts owner IDs. Application services use it for trial/managed create and
managed mutations. Private delivery uses the stored managed owner, avoiding a
namespace lookup on every public request while no transfer/release operation
exists.

### 2.3 Content management representation

Extend `ContentTypeHandler` with a management-source method, named
`to_input(data)`, whose output is the safe editable representation accepted by
that handler's `validate` method. It must not expose stored derivations or
backend fields.

`MdPageHandler.to_input` returns only:

```ts
{ md: string; css?: string }
```

It never returns derived HTML. Add handler tests proving
`validate(to_input(derive(valid_input)))` succeeds and preserves source.

## 3. Page repository contract

Replace locator-only `ContentRepository` with `PageRepository` under
`lib/page/interfaces.ts`. Storage owns atomic identity/index/revision
conditions; services own validation, authorization, derivation, and HTTP-free
business results.

Required operations:

1. `find_by_locator(locator)` — direct resolution.
2. `find_by_id(page_id)` — management resolution.
3. `list_managed(request)` — bounded records for one owner, optional normalized
   namespace filter, deterministic order, opaque continuation cursor.
4. `put_trial(request)` — atomically create or replace only an absent/trial
   locator; never replace managed.
5. `create_managed(request)` — atomically create at an absent locator or replace
   a trial; conflict with any managed locator.
6. `replace_managed(request)` — atomically replace one managed page only when
   page ID, owner ID, and expected revision match; increment revision once.
7. `delete_managed(request)` — atomically delete only when ID, owner, and
   expected revision match.

Typed repository outcomes distinguish:

- success with the complete stored record;
- managed-locator conflict;
- not found/not owned (one non-disclosing result);
- revision conflict;
- generated page-ID collision where creation may retry.

Repository methods must not infer authority from a locator supplied by the
browser. They compare stored stewardship for atomic conditions, while the
service separately verifies current namespace ownership.

### 3.1 Ordering and pagination

Initial list order is locale-independent and stable:

1. normalized namespace;
2. default page before named pages;
3. normalized page name;
4. page ID as a final tie breaker.

HTTP defaults `limit` to 50 and bounds it to 1–100. The cursor encodes the last
logical sort tuple and active namespace filter as bounded base64url JSON. It
contains no owner ID or secret. Invalid, padded, oversized, or filter-mismatched
cursors return a typed invalid-cursor result; every page is still selected by
the server-derived owner ID.

### 3.2 Repository conformance

Create `lib/page/repository-conformance.ts` and run it unchanged against memory
and Deno KV. Cover:

- ID and case-insensitive locator round trips;
- original locator casing;
- trial public invariant;
- trial create/replacement and managed conflict;
- managed creation over absent/trial records;
- managed creation conflict without changing the winner;
- owner isolation;
- ID and locator uniqueness;
- deterministic owner/namespace listing and cursor continuation;
- source/meta/date/revision round trip;
- successful revision increment;
- stale update/delete rejection;
- content/access coherence under concurrent replacement;
- exactly one concurrent managed create at one locator;
- trial/managed race: managed content cannot be overwritten once committed;
- deletion of ID and locator visibility;
- large content and binary-safe stored values supported by the contract.

Memory storage must return isolated values (use `structuredClone` at its
boundary) so caller mutation cannot alter repository state.

## 4. Application service contracts

Implement `PageService` in `lib/page/service.ts` satisfying narrow interfaces:

- `TrialPagePublisher`;
- `ManagedPageCreator`;
- `ManagedPageLister`;
- `ManagedPageInspector`;
- `ManagedPageUpdater`;
- `ManagedPageDeleter`;
- `PageDeliverer`.

The service owns the only valid record-production path and retains the current
`validate -> derive -> render -> metadata` invariant.

### 4.1 Trial publish

Input: guest actor, locator, explicit `access`, content type, untrusted input.

Sequence:

1. Validate/round-trip the locator through `LocatorEngine`.
2. Require `access === "public"`; private trial returns typed
   `private_requires_managed_page`.
3. Resolve namespace authority and require `unreserved`.
4. Select and validate the content handler.
5. Derive stored data and delivery metadata.
6. Call `put_trial` with a generated page ID and current time.
7. Retry bounded page-ID collisions.
8. If storage observes a managed record after authorization, return the same
   public `namespace_reserved` result; do not overwrite.

A trial replacement may preserve its internal page ID/created time or replace
them according to the repository contract, but no management promise is exposed.
The chosen contract will preserve ID/created time and increment revision for
simpler atomic storage; trial clients still receive no ownership guarantee.

### 4.2 Managed create

Input: authenticated actor, locator, explicit access, content type/input.

Sequence:

1. Validate locator.
2. Require namespace authority `owned`; map unreserved to
   `namespace_not_reserved` and another owner to `namespace_reserved`.
3. Validate public/private access.
4. Validate/derive/render content.
5. Build a new managed record with server actor ID, generated page ID, revision
   1, and one timestamp.
6. Call `create_managed`; an existing trial is replaced atomically, while an
   existing managed page returns `page_exists` without replacement.
7. Retry only generated ID collision, never locator conflict.

### 4.3 List and inspect

Both require an authenticated user actor.

- List uses only the actor user ID. If a namespace filter is supplied, validate
  it as a namespace and require it to be owned before querying.
- Return summaries without content source: page ID, locator/path, access, content
  type, size, timestamps, revision.
- Inspect loads by page ID, compares managed owner, verifies current namespace
  ownership, selects the handler, and returns the handler's `to_input` source.
- Missing, trial, other-owner, or no-longer-authorized records collapse to
  `not_found`; no user IDs leak.

### 4.4 Update

Input: actor, page ID, expected revision, and a patch with optional `content`
and/or `access`. At least one field must be present.

1. Load by ID and require managed ownership by the actor.
2. Verify the actor still owns the page namespace.
3. Validate explicit access when present.
4. Validate/derive/render explicit replacement content when present; omission
   preserves the stored content exactly.
5. Build one complete replacement with unchanged ID/locator/stewardship/created
   time, incremented revision, and current `updated_at`.
6. `replace_managed` checks the original expected revision atomically.
7. Return `revision_conflict` if another mutation won; never retry by silently
   rebasing caller intent.

Content and access in one PATCH commit together. Access-only updates retain the
same content data and metadata. The locator is not patchable in this task;
future rename will be an explicit locator operation against the stable ID.

### 4.5 Delete

Load/authorize as update, then call revision-bound `delete_managed`. A stale
revision returns conflict; missing/non-owner stays non-disclosing `not_found`.
Deletion removes current direct delivery immediately after commit.

### 4.6 Direct delivery

`deliver(locator, actor)` loads by locator before handler rendering:

- public trial/managed page: deliver to everyone;
- private managed page: deliver only when actor user ID equals stored owner;
- private trial or malformed authority state: fail closed as not found/corrupt;
- unauthorized private: return the existing `not_found` result before handler
  lookup, making retired content types indistinguishable from missing;
- authorized unknown handler: internal undeliverable result.

Retain raw body, length, media type, disposition, no-store, nosniff, and active
content sandbox exactly. The Fresh catch-all supplies `PageActor` from resolved
session; direct content remains UI-free.

## 5. HTTP API contract

Implement a Fresh-independent `PageHttpHandler`/adapter in `lib/page/http.ts`.
Routes only pass `Request` and typed `AppRequestContext`.

All JSON request objects are strict: reject arrays, duplicate/unknown query
parameters, unknown top-level fields, wrong types, padded IDs/cursors/revisions,
and unsupported content types with typed errors. Keep bounded body reads before
JSON parsing. All management and error responses use `Cache-Control: no-store`
and include no owner/session IDs.

### 5.1 Shared create endpoint — `POST /api/pages`

Request body:

```json
{
  "locator": {
    "namespace": "Alice",
    "page_name": "notes/today"
  },
  "access": "private",
  "content": {
    "content_type": "md-page",
    "input": {
      "md": "# Notes",
      "css": "body { color: navy; }"
    }
  }
}
```

`page_name` is omitted for a default page. `access` is always required; guests
must explicitly send `public`. This removes all omitted-access ambiguity.

Session-derived semantics:

- guest: trial create-or-replace, public only, unreserved namespace only;
- authenticated: require exact `x-csrf-token`, then managed create in an owned
  reserved namespace; no silent fallback to trial.

A stale creator form includes its old CSRF header but resolves as guest; return
`401 not_authenticated` rather than trial-publishing. The browser keeps its
local draft because errors do not clear form state.

Responses:

- `201` for a newly created trial or managed page;
- `200` for trial replacement;
- `Location` is the direct path for trial and `/api/pages/{page_id}` for managed;
- managed success includes `ETag`;
- JSON includes `outcome`, a page summary, and exact direct `path`/absolute
  `url`; managed output additionally identifies its management URL.

Failures:

- 400 malformed/ambiguous request;
- 401 stale creator intent/not authenticated where management was attempted;
- 403 invalid CSRF, private trial, platform/reserved/other-owner namespace;
- 409 creator namespace unreserved or managed page already exists;
- 413 body too large;
- 415 non-JSON;
- 422 valid JSON with invalid locator/content.

### 5.2 List — `GET /api/pages`

Authenticated only. Query fields:

- optional `namespace`;
- optional `limit` (default 50, maximum 100);
- optional opaque `cursor`.

Return `200`:

```json
{
  "ok": true,
  "pages": [
    {
      "page_id": "...",
      "locator": { "namespace": "Alice", "page_name": "notes/today" },
      "path": "/Alice/notes/today",
      "access": "private",
      "content_type": "md-page",
      "size_bytes": 1234,
      "created_at": "...",
      "updated_at": "...",
      "revision": 2,
      "management_url": "/api/pages/..."
    }
  ],
  "next_cursor": null
}
```

No source or owner ID appears in list output. Namespace filters not owned by the
caller return 404 to avoid disclosing claims through this surface.

### 5.3 Inspect — `GET /api/pages/:page_id`

Authenticated owner only. Return the summary plus:

```json
"content": {
  "content_type": "md-page",
  "input": { "md": "# Notes", "css": "..." }
}
```

Set `ETag: "page-{page_id}-r{revision}"`. Missing, trial, or non-owner IDs all
return the same 404. Validate page IDs before service lookup.

### 5.4 Update — `PATCH /api/pages/:page_id`

Authenticated owner only. Require:

- exact `x-csrf-token`;
- exact single `If-Match` ETag from inspect/list/update;
- JSON object containing `access`, `content`, or both.

Examples:

```json
{ "access": "private" }
```

```json
{
  "content": {
    "content_type": "md-page",
    "input": { "md": "replacement" }
  }
}
```

Omitted fields are unchanged by explicit PATCH semantics. Return `200`, complete
inspect representation, and the next ETag.

- Missing `If-Match`: 428 Precondition Required.
- Malformed/wildcard/multiple ETag: 400.
- Stale well-formed ETag: 412 Precondition Failed.
- Empty patch: 400.
- Invalid content/access: 422.
- Missing/non-owner: 404.

### 5.5 Delete — `DELETE /api/pages/:page_id`

Authenticated owner only. Require exact CSRF and `If-Match`; accept no body.
Return 204 with no body. Use the same 400/401/403/404/412/428 distinctions as
PATCH. A repeated delete is 404.

### 5.6 CSRF boundary

Extract constant-time synchronizer comparison from namespace HTTP code into
`lib/http/csrf.ts` and reuse it. CSRF remains an HTTP/session concern and never
enters page services or repositories. The current browser-session API model is
retained; general programmatic bearer credentials remain out of scope.

## 6. Storage implementations

### 6.1 Memory

Create `MemoryPageRepository` with maps by page ID and normalized locator plus a
managed owner index. Every conditional mutation runs synchronously through its
check/set phase so concurrent promises serialize on the event loop. Clone values
at reads/writes. Implement deterministic sorted pagination from logical keys.

### 6.2 Deno KV keyspace

Use a fresh keyspace and schema version 1; do not read the old
`content-pages` envelopes:

```text
["iam-pager", "pages", "by-id", page_id]
["iam-pager", "pages", "by-locator", namespace_key, default_rank, page_name_key]
["iam-pager", "pages", "by-owner", owner_user_id,
 namespace_key, default_rank, page_name_key, page_id]
["iam-pager", "pages", "chunks", page_id, generation, chunk_index]
```

- `default_rank` is 0 for default, 1 for named; empty page names are invalid, so
  the remaining key is unambiguous.
- Locator index values contain only page ID and schema version.
- Owner index values contain page ID/revision or a minimal validated locator
  summary; envelope remains authoritative.
- Envelope stores locator casing, stewardship, access, revision, timestamps,
  content meta, generation/chunk metadata, and data codec.
- Content data remains chunked immutable JSON as today.

Atomic behavior:

- Write new content chunks before the visibility commit.
- Trial put checks locator index and existing envelope; absent/trial may commit,
  managed rejects. It updates envelope/index together and removes replaced trial
  generation.
- Managed create checks generated ID absent and locator state; absent/trial may
  commit, managed conflicts. Replacing trial atomically removes its ID/index and
  chunks while adding managed ID/locator/owner records.
- Content PATCH checks envelope version/revision/owner, flips generation, and
  keeps all indexes coherent.
- Access-only PATCH checks and updates only the envelope; it reuses the current
  immutable generation.
- Delete checks revision/owner and removes envelope, locator index, owner index,
  and generation chunks together.
- Failed conditional writes clean their just-written generation best-effort;
  crashes may leave unreferenced chunks as the existing documented limitation.
- Retry only storage contention that does not represent a caller revision or
  locator conflict; cap retries and return/throw distinct contention failure.

Validate every envelope/index field, date, revision, access/stewardship
combination, key/value identity, chunk count/order, and data byte length. Unknown
schema or impossible trial/private records are corruption, never interpreted
loosely.

Continue requiring durable ownership for durable page storage and the same Deno
KV database path. Rename the TypeScript factory boundary to page repository while
retaining `IAM_PAGER_CONTENT_STORAGE_BACKEND` for deployment continuity; its
documented meaning becomes page/content persistence.

## 11. Verification matrix

### Domain/service

- Guest public create and replacement in unreserved namespace.
- Guest private rejected.
- Guest reserved namespace rejected across casing.
- Authenticated managed create requires owned reservation.
- Managed create replaces trial at identical case-insensitive locator.
- Managed create conflicts with managed page and never changes it.
- Default/named pages remain distinct.
- Owner list/inspect only; source excludes derived HTML.
- Public/private access update independent from content update.
- Content/access combined patch commits one coherent revision.
- Non-owner cannot infer managed page through inspect/update/delete.
- Delete removes direct resolution.
- Unknown handlers and invalid inputs remain typed.

### Concurrency/storage

- Concurrent managed creates: exactly one managed winner.
- Concurrent trial writes: one complete trial winner.
- Trial racing after managed commit cannot overwrite; receives conflict.
- Managed create racing trial either replaces trial or makes trial lose; final
  managed page is complete.
- Two PATCH requests with one ETag: exactly one succeeds, one gets revision
  conflict.
- PATCH versus DELETE with one ETag: exactly one succeeds.
- Access-only KV patch retains exact generation bytes/chunks.
- Content patch swaps generation without mixed metadata/access.
- Owner/locator indexes have no dangling visible entries after success.
- Large multi-chunk data, corruption, contention exhaustion, and orphan limits.

### HTTP/security

- Strict create/list/item/update/delete request decoding and body/query bounds.
- Guest/authenticated dispatch based only on resolved session.
- CSRF missing/wrong/cross-session rejected for every authenticated mutation.
- Stale creator request cannot downgrade to trial.
- ETag syntax, 428 missing, 412 stale, new ETag on success.
- Stable no-store JSON/status/error shapes without IDs other than page ID.
- Private direct response: owner 200; guest, logged-out owner, other user all
  exact ordinary 404 body/status/cache behavior.
- Authorization occurs before content-handler error disclosure.
- Active-content CSP, length, disposition, cookie, and request-ID preservation.

### Final gates

Run:

```sh
deno task check
deno task test
deno task build
```

Then local-mode smoke:

1. guest publishes public trial and opens it;
2. rejected guest publish retains the complete draft;
3. creator signs in and reserves a namespace;
4. API creates managed public page over a trial locator;
5. API creates private page;
6. owner inspects and directly opens private page;
7. separate guest session gets ordinary 404;
8. PATCH access with ETag changes delivery immediately;
9. stale ETag fails without mutation;
10. DELETE removes API/direct access;
11. logout makes private direct access return ordinary 404.

## 13. Failure and rollback considerations

- Startup/configuration remains compatible, but old page records are invisible
  in the fresh keyspace. Document deleting development KV rather than attempting
  fallback reads.
- Never dual-write old and new repositories; partial dual behavior would make
  delivery and management disagree.
- A failed create/update before visibility commit may orphan chunks but cannot
  expose partial content. Cleanup is best effort and the limitation remains
  documented.
- HTTP adapter failures after a committed mutation must be diagnosable by
  request ID; clients can inspect by page ID rather than blindly retry create.
- Retrying POST after a lost managed-create response may return `page_exists`;
  the response should include no conflicting page details. Idempotency keys are
  later scope.
- ETag preconditions prevent blind retry from overwriting newer state.
- No UI success state may be treated as authority; a refreshed API read is
  definitive.

## 14. Acceptance criteria

The task is complete only when all are true:

1. No application mutation path can create a private trial page.
2. No trial write can replace a committed managed page, including concurrent
   storage operations.
3. Managed pages can be created, listed, inspected, content/access patched, and
   deleted through documented APIs without management UI.
4. Managed creation replaces pre-existing trial content and conflicts with an
   existing managed locator.
5. Every managed mutation derives user authority from session plus namespace
   reservation and validates CSRF at HTTP.
6. Every update/delete is revision-bound and has deterministic conflict
   behavior.
7. Private raw content is delivered only to its stored creator and is ordinary
   missing to everyone else.
