# Plan step 7 delivered: strict page HTTP boundary

Implemented the Fresh-independent page API adapter from [[003.plan]]:

- `PageHttpAdapter` maps collection create/list and item inspect/PATCH/DELETE to
  the HTTP-independent page service contracts. It derives guest or creator
  authority only from the resolved session and rejects stale creator CSRF intent
  on a guest session instead of downgrading to trial publishing.
- Create and PATCH use bounded JSON reads and strict nested object schemas.
  Listing rejects unknown/duplicate/oversized query fields, non-canonical limits,
  and invalid cursors. Item requests validate one route-safe page ID.
- Authenticated mutations require the exact `x-csrf-token` via a shared
  fixed-length comparison extracted to `lib/http/csrf.ts`; namespace reservation
  now reuses the same primitive.
- Canonical strong page ETags bind page ID and revision. PATCH and DELETE require
  one exact `If-Match`, distinguish missing/malformed/stale preconditions as
  428/400/412, and return the next validator after update.
- Owner-safe presenters serialize timestamps and editable source without owner
  IDs or stored derivations. Every JSON, error, and management response is
  no-store; private/non-owner management lookup remains a generic 404.
- Added `docs/api/pages.md` as the concrete adapter contract, explicitly marked
  pending Fresh composition, and synchronized README/specification current-state
  sections.

Thirteen new adapter/ETag/CSRF tests cover guest replacement, managed create,
strict decoding, stale creator intent, listing/pagination, source inspection,
CSRF, preconditions, atomic update/delete mappings, and method rejection. Check,
build, and all 406 tests pass.

Next: plan step 8, select `PageRepository` storage in composition, expose the page
service/HTTP interfaces from `AppServices`, and move Fresh collection/item routes
to this adapter without retaining the old mutation path.
