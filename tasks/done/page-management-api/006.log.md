# Plan step 5 delivered: HTTP-independent PageService

Implemented the application layer from [[003.plan]] against the memory page
repository:

- `PageActor` and `NamespaceAuthorityResolver` keep user/guest and reservation
  decisions independent from HTTP and sessions; the repository-backed resolver
  returns only unreserved/owned/reserved-by-other, never another owner ID.
- `PageService` satisfies narrow trial publish, managed create/list/inspect/
  update/delete, and direct-delivery interfaces. It validates locators and
  access, requires current namespace ownership, retries generated-ID collisions
  within a fixed bound, and is the new page model's only record-production path.
- Content always follows validate -> derive -> render -> metadata. Management
  summaries omit source, stewardship, and owner IDs; inspection recovers only
  handler-approved editable input and never derived HTML.
- Trial pages are public-only and cannot replace managed records. Managed create
  atomically replaces a trial but conflicts with managed content. Updates and
  deletes are revision-bound; combined content/access updates commit once,
  access-only updates preserve exact content, and stale concurrent changes do
  not rebase.
- Public pages deliver to every actor. Private pages deliver only to their stored
  owner; unauthorized requests become ordinary not-found before content-handler
  lookup, preventing retired-type disclosure.
- Hardened record validation to reject unknown stewardship kinds and prevented
  access-only mutation of retired content when the required inspection response
  could not be produced.

Updated README and specification current-state text. Check, build, and all 359
tests pass (17 new focused tests).
