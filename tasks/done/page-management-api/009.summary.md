# Page management composed into the running application

Plan steps 1-10 are delivered. `lib/page/` now provides the invariant-checked
model, atomic repository contract, conforming memory and Deno KV adapters,
namespace-authority resolver, HTTP/session-independent `PageService`, strict
management HTTP adapter, and direct-delivery HTTP mapping.

The composition root selects `PageRepository` through the retained
`IAM_PAGER_CONTENT_STORAGE_BACKEND` deployment variable, constructs one page
service over one handler registry/locator/authority/clock, and exposes its raw
application and HTTP interfaces. Fresh collection and item routes now serve
create/list/inspect/PATCH/DELETE, while the catch-all derives guest/user authority
from the resolved session and uses the same service for public and owner-private
delivery.

The existing publishing form now sends the nested explicit public-create body
and creator CSRF token through an interface-backed presenter model. Draft values
remain untouched on API errors. README, the concrete API contract, specification,
and changelog describe the composed behavior. Check, build, and all 411 tests
pass.
