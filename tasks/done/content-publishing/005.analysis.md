# MdPage content type and in-memory repository

Scope of this step: the first `ContentTypeHandler` implementation (`MdPage`),
the first `ContentRepository` implementation (in-memory), and the repository
interface rework that fixes carry-over item 6 from [[004.review]]. Still no HTTP
wiring and no publish/deliver use-case functions.

## Markdown dependency: `jsr:@deno/gfm`

Requirements: server-side md -> html at publish time (derive-once decision in
[[003.analysis]]), safe for guest-supplied input, synchronous (matches
`derive`'s signature).

- **Chosen: `@deno/gfm`** — Deno-team maintained, JSR-native, GitHub-flavored
  markdown, and sanitizes output by default via `sanitize-html`. One dependency
  covers rendering and sanitization; probe confirmed `<script>` is stripped from
  output. Render is synchronous.
- _Rejected: `npm:marked` + DOMPurify_ — DOMPurify needs a DOM; in Deno that
  means a jsdom/linkedom shim. Two dependencies plus a DOM shim for what
  `@deno/gfm` does alone.
- _Rejected: `npm:micromark`_ — no built-in sanitizer; same extra-sanitizer
  problem.

Trade-off accepted: `@deno/gfm` emits GitHub-style extras (heading anchors with
inline SVG octicons). Harmless in raw delivery; revisit only if output weight
matters.

## CSS handling

`MdPage` stores optional raw `css` and applies it only in the raw delivery
document (`render` wraps derived html in a standalone page with a `<style>`
tag). Decisions:

- **`</style>` breakout is neutralized** by escaping `<` as the CSS escape `\3c`
  before embedding. Without this, css could close the style tag and inject
  markup — the one path around the sanitized markdown.
- **Residual css risks are accepted on raw pages**: css cannot execute script,
  and per DA-CONTENT the raw response is isolated from management sessions;
  exfiltration-style css tricks (`url()`, `@import`) remain possible and are
  recorded as an open risk. Guest css must never be injected into site-wrapped
  views — only the raw document.

## MdPage shape

- `MdPageInput = { md, css? }` — `md` required non-empty string, `css` optional
  string (001.draft).
- `MdPageData = { md, html, css? }` — original `md` kept (source of truth for
  copy/duplicate flows), `html` derived once at publish time.
- `render` returns a full standalone HTML document with
  `text/html; charset=utf-8`, since raw delivery is an unwrapped page.

## Repository rework (fixes review item 6)

`ContentRepository` now speaks `Locator` and `PageRecord`:

- `PageRecord = { locator, content }` — carries the publisher-cased `Locator`
  next to the `ContentRecord`, so DA-LOCATOR's "display original casing" is
  satisfiable from storage.
- `get(locator)`, `put(page)`, `delete(locator)` — keys are derived internally
  via `locator_key`, so callers cannot produce a key/locator mismatch and
  case-insensitive identity is enforced by construction.
- `put` stays create-or-replace (guest flow, [[001.draft]]).

Interface change is cheap now: one implementer, zero call sites. This was the
reason review item 5 (sync `derive`) stayed unchanged too — `@deno/gfm` renders
synchronously, so no signature change is needed.

`MemoryContentRepository` is a `Map` behind the interface — enough for the guest
slice (001.draft demands no durability for guest pages); a durable
implementation can satisfy the same interface later (QT-BOUNDARIES).
