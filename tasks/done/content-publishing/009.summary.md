# First publishing slice complete

Implemented the task from locator to browser flow:

- `LocatorEngine` registers mapping strategies, applies forbidden namespaces,
  and now rejects publish-side locators that do not round-trip unchanged through
  the active mapping. `PathSlugStrategy` maps the namespace to the first path
  segment and an optional multi-segment page name to the remainder.
- Content is interface-first (`ContentTypeHandler`, `ContentRepository`) with
  `MdPageHandler` and `MemoryContentRepository`. Markdown is sanitized and
  derived at publish time; optional CSS has style-tag breakout neutralized.
- `PublishingService` is the sole producer of stored records and owns
  `validate -> derive -> render`, create-or-replace semantics, and metadata
  derivation from the rendered payload.
- HTTP delivery serves all valid unclaimed locator paths without the site shell,
  with explicit statuses, metadata headers, `no-store`, disposition, `nosniff`,
  and an origin-less CSP sandbox for active content.
- The site shell is served at `/` and `/site/*`; `site` and `api` are forbidden
  namespaces.
- Guest `MdPage` placement is available through bounded `POST /api/pages` JSON
  and a Fresh form. Success returns and links to the direct path. The form warns
  that guest paths are replaceable, process-local, and excluded from browsing.
- Prototype limits are 96 KiB per API request, 64 KiB Markdown, and 16 KiB CSS,
  measured as UTF-8 bytes.

Verification: 72 tests pass, `deno task check` is clean, production build
succeeds, and a production-server smoke test covered home rendering, API
publishing, and direct delivery.

Deferred beyond this task: durable storage; total page capacity, frequency, and
expiry limits; namespace reservation/authentication; search; full locator
character policy; cache validators; and external storage.
