# Ready for review

Implemented an interface-backed deterministic physical-line engine in
`lib/ui/markdown-line-editor.ts`. Untouched Markdown round-trips exactly;
recognized headings, lists, and whole-line links receive focused forms, while
unfamiliar syntax remains an editable raw line. All mutations return a new line
array and serialize through the existing Markdown callback.

Added switchable Raw and Steps modes with compact previews, save/cancel updates,
two-step deletion, movement, and insertion above or below. New line choices are
text, six-level headings, bulleted lists, numbered lists, links with separate
label and URL fields, and blank lines. Unsaved focused edits are guarded when
switching modes, and Steps declines to render more than 500 physical lines to
avoid a mobile DOM failure.

Publishing, preview, validation, content derivation, and storage still consume
the same raw Markdown string. Updated README, quality requirements, changelog,
and mobile-first styling.

Verification: `deno task check`, all 85 tests, and `deno task build` pass. The
Raw, compact Steps, expanded edit, and insertion-picker states were inspected in
headless Chromium at a 390 by 844 mobile viewport.

Review focus: touch flow and labels in `components/MarkdownContentEditor.tsx`,
and whether the intentionally physical-line interpretation matches the desired
editing granularity.
