# Soften and contextualize editor controls

Improve the guest publishing form as one coherent hierarchy rather than a set of
large labels and detached helper buttons.

## Acceptance criteria

- Field and section labels remain accessible but use subdued visual weight and
  scale.
- Namespace and optional page-name Random actions sit inside the trailing edge
  of each input context instead of appearing as separate header buttons.
- Similar optional controls are visually attached to the context they affect.
- Markdown and CSS share one source area and are switchable; both source editors
  are never shown simultaneously.
- The complete Page editing section can be collapsed and restored without
  resetting its selected source, layout, or draft.
- Layout switches explicitly between `Split with preview` and `Full width`;
  split places source and preview side by side where space permits, while full
  width places preview below the source.
- Live preview has an accessible fullscreen enter/exit control.
- Guided Markdown section previews size to their complete content by default.
  Each section can independently switch to compact height and back.
- Per-section compact/whole choices survive Markdown changes and section focus
  changes rather than being derived from transient component focus or content
  keys.
- Mobile layout, keyboard operation, status messaging, documentation, tests,
  formatting, lint, type checks, and build are review-ready.
