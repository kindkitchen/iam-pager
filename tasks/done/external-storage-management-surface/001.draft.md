# Management surface - draft design

## API (shape to finalize against existing api conventions in lib/api, routes/api)

- `GET  /api/storage/connections` - own connections; fields: connection_id,
  provider_id, provider_subject (display form), scopes, status, created_at.
  Token material structurally absent (asserted by contract test).
- `POST /api/storage/connections/google-drive/disconnect` - revoke + mark
  revoked; response includes count of assets that will become missing (or
  the block, per the spec decision on disconnect-with-dependents).
- Connect itself stays a browser redirect flow (step 5 routes), the API only
  links to it.
- Publish/replace payload extension: optional
  `storage: { connection_id }` -> content uploaded via provider
  `put_content`, asset created with external source; validation errors:
  unknown connection, revoked connection, provider without `write`.

## UI

- Settings/management area: `ConnectedStorages` component + island -
  provider cards (Google Drive first), connect button, status, disconnect
  with confirmation listing dependent pages.
- Publish/replace form: storage selector shown only when an eligible
  connection exists; default remains local/inline.
- Follow conventions: kebab-case files, CamelCase components, logic in lib/
  (web is a projection - the publish-to-external logic lives in lib/page /
  lib/external-storage services, routes only bind it).
