# Completed locator-management core foundation

Implemented explicit `ManagedPageRenamer` and `ManagedPageDuplicator` service
contracts plus atomic repository operations in memory and Deno KV.

- Rename stays inside the reserved namespace, retains page ID/content/access and
  creation time, moves locator and owner indexes at one expected revision,
  reports managed conflicts, and can retire a trial destination.
- Duplicate uses the shared runtime-neutral four-word generator, retries occupied
  names and generated ID collisions within bounds, and copies the exact expected
  source revision into a fresh ID without changing the source.
- Shared conformance covers conflict, non-disclosure, index movement, trial
  replacement, snapshot copying, and concurrent destination claims on both
  backends; service tests cover validation, generated retries, default-page
  rename, and exhaustion.
- Updated README, API status, and DS-MANAGE/CP-MANAGE/EX-MANAGE/addressing/
  technical specifications. The API and creator panel deliberately do not expose
  these operations yet.

Validation: `deno task check`, 404 tests, and `deno task build` pass.

Next: add bounded page tags and tag-aware managed/public filtering at the raw
contracts before exposing the expanded management HTTP layer.
