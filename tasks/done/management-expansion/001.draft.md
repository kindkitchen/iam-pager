# Expanded authenticated management (DS-MANAGE)

## Scope

Contracts first in `lib/page` (each operation an explicit interface behavior
with tests, and repository conformance wherever storage is touched):

- rename within the reserved namespace: a conflict with another protected page
  is reported, never a silent replacement (EX-MANAGE);
- duplicate: a generated non-conflicting name following the existing generator
  direction;
- tags on managed pages: bounded and validated; tags on public pages become
  explorable through the `public-exploration` contract;
- managed filtering: name, access, and tags first; dates and views only where
  the metadata is already useful and trustworthy (DS-MANAGE);
- bulk deletion and access changes over an explicit selection with a per-page
  result.

Then API: extend `docs/api/pages.md` operations with the same session,
synchronizer CSRF, and revision discipline as the existing mutations. Then UI:
extend the `creator-management-ui` surface.

## Non-goals

- namespace release or transfer;
- external storage (DS-EXTERNAL);
- view counters.

## Acceptance

- Contracts, conformance (memory + Deno KV), API, and UI delivered in that
  order; each layer green before the next.
- Spec updates in the same change: DS-MANAGE in `delivery-slices.md`,
  CP-MANAGE in `capabilities.md`, EX-MANAGE in `experiences-and-scope.md`;
  `docs/api/pages.md` updated with the surface.
- CHANGELOG entry; check and the full test suite green.

## Invariants (project conventions to preserve)

- Interface-first: capability contracts live in `lib/` and are satisfied by
  implementations; consumers depend on contracts only.
- Logic is web-independent: behavior lives in `lib/`; Fresh routes, islands,
  and components are one secondary projection of it.
- Specs first: `docs/specification/` (and `docs/api/` when the HTTP surface
  changes) update together with the implementation, never after.
- Deno with import map; std packages and default solutions over libraries.
- Naming: snake_case variables/properties, kebab-case files, CamelCase
  frontend components.
- `CHANGELOG.md` entry with every change; keep README and docs in sync.
- GitButler workspace: use `but` for commits; do not push.
