# Permit backend selectors in All contexts

Selected the simpler dashboard configuration where all three `deno-kv` backend
selectors apply to All contexts. This is valid under the current composition:
Build does not initialize storage, revision previews force process-memory
repositories despite inherited selectors, and Local intentionally uses the
Deno Deploy database connection when invoked through `deno ... --tunnel`.

The ownership KV path remains absent. If tunneled local development must later
remain process-memory-backed, selectors will instead be scoped to Production and
the non-production runtime context.
