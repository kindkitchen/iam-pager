# Completed local verification and manual schema release gate

Replaced deployment verification/mutation with three separate paths:

- `deno task verify` runs check and all tests through an installable native
  `pre-push` hook. Git and GitButler use the repository hook without Husky or a
  custom `core.hooksPath`.
- `deno task pre-deploy` only reads the attached durable database and requires
  an exact `iam-pager` project/schema manifest plus matching completed state.
  Missing, stale, future, pending, wrong-project, corrupt, unknown, and memory
  configurations fail without database mutation.
- `deno task db-schema:upgrade` is an explicit local operator command. It accepts
  only an official remote Deno KV connector URL, reads its token from
  `DENO_KV_ACCESS_TOKEN`, and requires exact project plus complete `from` and
  `to` vectors before the guarded storage-agnostic writer can mutate anything.

Version 0 now means only an absent manifest. The one-time `0 -> 1` bootstrap is
an explicit URL/project assertion, installs coordination metadata around the
already-format-1 legacy records, and publishes the project manifest last.
Subsequent project or source-vector mismatch performs zero writes. Interrupted
idempotent forward helpers remain resumable.

Deno KV implements the new manifest interface with compare-and-set publication;
the existing state/upgrader framework remains behind agnostic interfaces. The
current registry is `ownership:1,pages:1,sessions:1` for project `iam-pager`.
Revision timelines (`DENO_TIMELINE=preview/*`) now force all application storage
to memory because they share a database and skip pre-deploy; Git branch timelines
retain isolated durable storage and the read gate.

Pinned Deno 2.5.0 to the current Deploy builder/runtime, supplied missing package
types, and formatted the CSS with that formatter. Documentation now requires
backward-compatible expand/deploy/contract transitions because remote updates
precede deployments that require them.

Verification completed with the installed hook matching the tracked executable,
475 passing tests, formatting/lint/type checks, and the production build. A
local file-backed Deno KV integration also proved that an absent manifest blocks
pre-deploy, the explicit `0 -> 1` writer bootstraps it, and the same read-only gate
then passes. A real remote write was intentionally not attempted without an
operator-provided database URL and token.
