# Native-atomic durable page aggregates complete Phase 3

Phase 3 is complete. The former focused capability intersection is now the named
raw-code `PageAggregateRepository` interface. `PageService`, the memory
reference, and shared conformance depend on that contract; the compatibility
`PageRepository` path remains available for the selected raw adapter.

`KvPageAggregateRepository` composes the gateway-backed immutable-asset adapter
with an adjacent `iam-pager/page-aggregates/v2` keyspace. One strict envelope by
stable page ID stores the complete canonical/alternate endpoint set and one
immutable asset reference. Revision-bearing, case-normalized endpoint claims and
ordered canonical owner/public projections are explicit records. Trial create or
replacement, managed create or takeover, combined revision-bound update,
duplication, and deletion check every relevant envelope/index plus a strict
asset manifest and expose all visibility through one `native_atomic()` commit.
Assets publish before pages and are never deleted by page operations.

Reads reject malformed schemas, key/value mismatches, missing claims, revision
drift, and incoherent owner/public projections. Conditional failures retry at
most 16 times; ambiguous commit exceptions propagate. The proven worst-case
transaction—an eight-endpoint public source duplicated over eight distinct
trials that each own eight endpoints—uses 87 of Deno KV's 100 checks, retaining
13 checks of headroom.

The unchanged shared aggregate conformance passes against memory and durable
implementations. Durable-only coverage proves repository reconstruction, exact
v2 records, legacy-keyspace isolation, malformed envelope/index/manifest
failure, rejected-commit retry and exhaustion, all eight endpoints, complete
multi-trial retirement, and exact transaction headroom. All 533 tests pass.

Deployment composition, the schema registry, existing raw page records, and
`IAM_PAGER_CONTENT_STORAGE_BACKEND=deno-kv` selection remain unchanged. Next:
Phase 4 from [[004.plan]] — add manual, adjacent, repeat-safe, source-preserving
schema-v1-to-v2 migration plus an unmigrated-data readiness refusal before any
cutover.
