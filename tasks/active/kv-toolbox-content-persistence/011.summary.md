# Source-preserving migration completes Phase 4

Phase 4 is complete. The manual database registry now advances only `pages`
from schema version 1 to 2 through retained `pages-v1-to-v2`; ownership and
sessions remain at version 1. Runtime and deployment composition still select
the legacy raw page adapter.

The migration strictly reads every visible v1 envelope through the legacy
repository, proves exact locator and owner indexes, validates referenced chunks,
and tolerates only documented unreachable chunk generations. It deterministically
maps each source page to one canonical inline v2 aggregate plus immutable
manifest-backed content, with SHA-256-derived asset and payload identities.
Deterministic binary staging reuses only exact bytes. Destination asset,
aggregate, endpoint, owner, and public records are conditionally imported and
reverified; different pre-existing data fails closed. No v1 key is updated or
deleted.

A readiness record binds source count and fingerprint. The read-only probe
recomputes the source, validates the readiness record, and rechecks every v2
asset, payload, aggregate, and visibility index. Migration also rechecks source
and destination after readiness publication so a racing v1 write cannot permit
the schema manifest to publish success. Missing migration state, changed or
corrupt source, incomplete destination, and conflicts are refused.

Coverage includes empty and mixed trial/managed/private data, pre-tag v1
records, interruption before and after asset/aggregate/readiness publication,
concurrent identical runs, source writes racing readiness, corrupt envelope,
index and chunk fixtures, destination conflicts, absent manifests, orphan
indexes, and write-free reruns. All 542 tests, tracked-source formatting, lint,
type checks, and the production build pass.

aggregate interface behind an explicit readiness gate, retain the legacy
compatibility/fallback path, and prove application behavior plus shared database
selection before unblocking PDF HTTP work.
