# API keys

Make the API a complete automation surface for authenticated owners while
keeping the web a secondary projection of raw application logic.

Requirements:

- define the final vision in `docs/specification/` and exact wire contracts in
  `docs/api/` before implementation;
- expose no guest API-key lifecycle;
- let a browser-session-authenticated user create, read, update, and delete only
  their own API keys;
- let an API key perform every current owner API operation allowed by its
  permissions, except login/logout and API-key list/create/inspect/update/
  individual-delete;
- permit bearer-authenticated revoke-all when the key has delete permission;
  revocation includes the calling key and takes effect immediately;
- give each key a label, explicit permissions, and a nullable expiry for
  infinity;
- keep domain, authorization, and persistence rules behind interfaces under
  `lib/`; Fresh routes and components remain thin;
- implement the API before the optional web management projection;
- add focused unit, repository-conformance, HTTP-policy, integration, presenter,
  and regression coverage with each implementation link, then pass the complete
  repository verification and production build.

All requests and responses must remain strict and bounded. Credentials and their
hashes must never enter logs, errors, URLs, presentation models, or storage in
plaintext.
