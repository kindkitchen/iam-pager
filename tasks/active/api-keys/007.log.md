# Bearer principals authorize the page and namespace API (plan link 5)

Added the API principal resolver and permission policy over every existing
API operation:

- `lib/api-auth/`: `ApiPrincipal` model (guest / browser_user / api_key),
  `ApiRequestAuthenticator` with `BearerFirstApiRequestAuthenticator`
  (strict `Bearer <token>` scheme; a present `Authorization` header is
  authoritative, malformed/unknown/expired/revoked bearers fail with one
  non-disclosing 401 challenge and never fall back to the cookie; default
  construction fails closed on every bearer), and `ApiOperationPolicy` with
  `PermissionApiOperationPolicy` (guest → not_authenticated; browser user →
  CSRF on non-read; key → mapped explicit permission, no CSRF).
- `lib/page/http.ts` and `lib/namespace/http.ts` consume the authenticator
  and policy: `read` = list/inspect + namespace list, `write` = create,
  update, rename, duplicate, bulk access, namespace reserve, `delete` = page
  delete + bulk delete. Key-authenticated create is always managed; guest
  browser trial publication and all domain owner/revision rules unchanged.
  Namespace reserve now treats a missing body `csrf_token` as `invalid_csrf`
  (was 400) since key callers omit it.
- `lib/request-context.ts`: requests carrying an `Authorization` header skip
  cookie-session resolution entirely and receive a non-persisted
  `ephemeral_guest()` view (new `EphemeralGuestSessionSource` implemented by
  `SessionService`), so no session record or cookie is ever produced solely
  for a bearer request and middleware-level cookie fallback is structurally
  impossible.
- `lib/app.ts` shares one authenticator/policy pair across the page and
  namespace adapters; the API-key management adapter stays browser-only with
  bearer revoke-all as before.
- Tests: authenticator scheme/fallback suite, policy matrix suite, bearer
  lifecycle/denial/foreign-owner/no-fallback coverage in page and namespace
  HTTP tests, middleware bearer-cookie test, and a composition test proving
  bearer create + revoke-all self-invalidation end to end (549 total).
- Docs: pages API authentication section with the permission matrix, API-key
  contract cross-reference, README architecture bullet, CHANGELOG.

Gates: `deno task check` and `deno task test` pass.

Remaining links: 1 (specification documents), 7 (closure).
