# Status todo -> active; core lifecycle, HTTP surface, and contract landed

Implemented the feature core as the new `lib/api-key/` sibling module (logic
source) with the web layer as a thin client, covering chain links 2 and 4 of
[[003.plan]] plus the bearer revoke-all slice of link 5 and the `docs/api`
slice of link 1:

- `lib/api-key/`: model (label/permission/expiry rules, `all` expansion,
  canonical order, status), `ApiKeyService` (create with one-time
  `iamp_`-prefixed bearer, SHA-256 hash-only storage, collision retry, owner
  isolation, revision-bound update, revision-bound revoke, atomic revoke-all,
  `resolve_bearer`), `MemoryApiKeyRepository`, strong `"api-key-<id>-r<n>"`
  ETags, and `ApiKeyHttpAdapter`.
- HTTP: `GET|POST|DELETE /api/api-keys`, `GET|PATCH|DELETE
  /api/api-keys/:api_key_id`. Management is browser-session-only with CSRF and
  If-Match; explicit bearers on management paths get one non-disclosing 401
  without cookie fallback; collection DELETE is bodyless and is the only
  bearer-accessible operation (requires `delete`, revokes the calling key).
- Wiring: `api_key_repository`, `api_keys`, `api_keys_http` in `lib/app.ts`;
  thin Fresh routes under `routes/api/api-keys*`.
- Docs: `docs/api/api-keys.md` (bearer shape, permissions, matrix), stale
  no-bearer claim fixed in `docs/api/pages.md`, README architecture bullet,
