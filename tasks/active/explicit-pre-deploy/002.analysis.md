# Current Deno task-runner capabilities

Research was checked against the official Deno task-runner documentation,
Deno's configuration schema at tag `v2.9.3`, and the installed Deno 2.9.3 binary
on 2026-07-20.

Sources:

- <https://docs.deno.com/runtime/reference/cli/task_runner/>
- <https://github.com/denoland/docs/blob/main/runtime/reference/cli/task.md>
- <https://github.com/denoland/deno/blob/v2.9.3/cli/schemas/config-file.v1.json>

## Verified behavior

- A task may be a string or an object with `description`, `command`, and
  `dependencies`. It may have dependencies and no command, which is suitable for
  the top-level `pre-deploy` group.
- Dependency tasks run in parallel. The default concurrency is the CPU count;
  `--jobs`/`--concurrency` overrides it and `DENO_JOBS` supplies an environment
  default. Shared dependencies run once, cycles fail, and the dependent command
  starts only after every dependency succeeds.
- Deno 2.8+ prefixes concurrent output lines with their task name.
- Task names follow schema pattern `^[A-Za-z][A-Za-z0-9_\-:]*$`; therefore the
  requested `pre-deploy::...` names are valid. A local dependency-graph probe
  confirmed check/test/build run in parallel and upgrade runs afterward.
- CLI wildcard matching (`deno task "pre-deploy::*"`) also runs matching tasks in
  parallel, but wildcard strings are not expanded inside a task's `dependencies`
  array. A local 2.9.3 probe reports `Task not found: pre-deploy::*`. Exact
  dependencies are therefore required and are safer because they preserve the
  verification-before-mutation graph.
- Object tasks also support opt-in caching with `files`, `output`, and `env`.
  That cache fingerprints files and declared environment values, not current
  database contents. The schema-upgrade task must omit `files` so it always reads
  durable schema state and lets runner idempotency produce the no-op.
- `deno task --env-file=<file> pre-deploy` can supply deployment configuration to
  every task process without embedding environment-specific paths in `deno.json`.

The current main-branch configuration schema and the `v2.9.3` schema had the same
SHA-256 during research, so the planned object fields are both current and
supported by the installed toolchain.
