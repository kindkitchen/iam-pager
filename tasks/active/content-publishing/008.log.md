# HTTP wiring landed: /site alias, root SPA shell, catch-all raw delivery

Milestone: the domain layer is now reachable over HTTP; routes are thin adapters
and all mapping logic stays in `lib/` (project convention: web is one
representation of raw-code logic).

## Landed

- `lib/app.ts` — composition root: `create_app_services()` wires
  `PathSlugStrategy` into `LocatorEngine` (forbidden namespaces `site`, `api`),
  `MemoryContentRepository`, `MdPageHandler` into `PublishingService`;
  `app_services()` is the process-wide singleton for routes. `publishing` is
  typed `PagePublisher & PageDeliverer`, not the concrete class.
- `lib/publishing/http.ts` — `deliver_locator_path(engine, deliverer, pathname)`
  maps outcomes to intentional responses (QT-ROUTING, CP-DELIVERY):
  `invalid_segment` 400, `not_a_locator` / `forbidden_namespace` / `not_found`
  404, `unknown_content_type` 500, success 200 with media type, publish-time
  content length, `cache-control: no-store` (content is replaceable in place; no
  validators yet), inline/attachment disposition with ASCII fallback + RFC 5987
  `filename*`, and `nosniff`. Active HTML/SVG receives an origin-less CSP
  sandbox plus restrictive resource directives, isolating creator content from
  future authenticated management state (QT-CONTENT).
- Routes: `routes/[...path].ts` (catch-all GET delivery), `routes/index.tsx` +
  `routes/site/index.tsx` + `routes/site/[...path].tsx` all render
  `components/SiteApp.tsx` — the raw root and `/site/*` serve the site itself
  (001.draft). Remaining Fresh counter, example API/API2, logger, and shared
  state demos removed (`islands/Counter.tsx`, `components/Button.tsx`,
  `routes/api/[name].tsx`, `main.ts`).
- Tests: 7 in `lib/publishing/http.test.ts` (headers, disposition, every error
  status), 2 in `lib/app.test.ts` (end-to-end publish→deliver through the
  composition root, forbidden `site`/`api`). 57 total; `deno task check` clean.
- Smoke-tested against the dev server: `/`, `/site`, `/site/a/b` serve the
  shell; an unknown locator returns 404 with `no-store`.

## Notes

- `api` added to forbidden namespaces beyond the required `site`: route
  precedence already keeps `/api/*` off the catch-all, so publishing under `api`
  would create undeliverable pages (QT-ROUTING).
- Guest pages stay uncached (`no-store`) until etag/last-modified validators are
  introduced.
- README and QT-ROUTING now document the concrete prototype mapping, current
  in-memory limitation, and active-content boundary.

Next: guest creation flow on the site — publish API endpoint plus the site form
island that submits an `MdPage` and links to the returned path.
