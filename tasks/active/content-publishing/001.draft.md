# Content publishing feature

## Locator feature

- The locator engine must support many resolution strategies.
- A strategy is defined as an interface; any implementation that satisfies it
  plugs into the engine and works without further wiring.
- Current (first) strategy: for an incoming endpoint path, the first slug
  section is the namespace and everything after it — even when it spans many
  slugs — is the page name.

## Site routing

- The site page is an SPA with a `/site` alias.
- The raw domain root and `/site/*` serve the site itself, not raw content.
- Therefore `site` is forbidden as a namespace (at minimum this one; the
  forbidden list may grow).

## Content model

- Content CRUD operations are defined as interfaces first, so many content types
  become usable simply by satisfying them.
- First content type: `MdPage`, structured as:
  - required `md` string input;
  - implicitly derived `html` string representation;
  - optional `css` string applied during content representation.

## Guest flow

- On the site, a guest can create an `MdPage`; locator creation is part of this
  flow.
- The created page must then open by its locator.
- Per spec (updated 2026-07-17): guest pages are not searchable or browsable
  from the site; they are locatable only by direct URL for raw preview.
- The page created by guest is always place content by this location (so
  technically there is not update feature for guest)
