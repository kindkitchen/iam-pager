# Meta from render output; publish as sole producer

Settles the two invariants carried from [[006.review]] and lands the
publish/deliver use-case layer under `lib/publishing/`.

## Decision: ContentMeta is computed from `render` output at publish time

`render` is treated as deterministic for stored data. At publish time the
service runs the handler's `render` once and derives `ContentMeta`
(`media_type`, `size_bytes`, `download_filename`) from the returned
`DeliveryPayload`. Because delivery runs the same deterministic `render`,
stored meta cannot go stale next to the delivered payload (QT-ROUTING).
Alternative rejected: letting handlers report meta separately — a second
source of truth that can drift from the payload.

Consequence: content types must keep `render` deterministic; a type with
per-request output would need a contract change first.

## Landed with this decision

- `lib/publishing/interfaces.ts` — `PagePublisher` / `PageDeliverer`
  interfaces, `PublishRequest`, typed `PublishResult` / `DeliverResult`
  unions (`forbidden_namespace`, `unknown_content_type`,
  `invalid_input` + detail; `not_found`, `unknown_content_type`).
- `lib/publishing/service.ts` — `PublishingService` implementing both:
  forbidden-namespace check via the engine, handler registry keyed by
  `content_type` (duplicates rejected), `validate -> derive -> render`
  pipeline as the only path into the repository ([[006.review]] item 1),
  create-or-replace keeps `created_at`, injectable clock, success returns the
  public path via `engine.format`.
- 11 tests in `lib/publishing/service.test.ts` (48 total), covering the
  sanitization invariant, meta/payload agreement at delivery, cross-case
  republish/delivery, and all error reasons. `deno task check` clean.

Still open: [[004.review]] item 2 (forbid `/` in namespaces via charset
validation); repository returns live references ([[006.review]] item 3).
