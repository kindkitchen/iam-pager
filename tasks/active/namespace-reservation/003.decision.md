# Specification has priority over implementation

Supersedes the divergence wording in [[002.plan]] (intro and S7), which allowed
amending the specification "in the same change set" as a diverging
implementation. That direction was wrong.

Corrected policy:

- The specification is the authority. An implementation proposal that does not
  match the spec is rejected early — it does not proceed and wait for the spec
  to catch up, and it is not merged with a compensating spec edit.
- Development may still inspire specification changes. The order is fixed:
  update the specification first, settle it as a spec change on its own, and
  only then continue implementing against the updated spec.
- S7 is therefore a conformance check, not reconciliation: it verifies that
  the built behavior matches the specification and that docs (README,
  CHANGELOG, capability status lines) describe that behavior. It never adapts
  the spec to what was built.
