# Map route steps (beta preview)

A feature preview of the Markdown step editor extended with a **map step**,
served at `/beta/**`. Nothing in the shipped publish flow
(`components/MarkdownContentEditor.tsx`, `/site/publish`) is touched: the
preview is an additive surface built from the same section model plus
`lib/maps/`.

## Surface

| Path                | Purpose                                                |
| ------------------- | ------------------------------------------------------ |
| `/beta`             | The preview editor.                                    |
| `/beta/<any/path>`  | Same editor; the requested path is echoed on the page. |
| `/beta/expand-link` | `POST {url}` — expands an official Google short link.  |

Files:

- `lib/ui/map-route-steps.ts` — step model and editing contract
  (`MapRouteStepEditor`)
- `lib/ui/map-link-expansion.ts` — short-link expansion service
  (`MapLinkExpansionService`)
- `lib/ui/beta-preview.ts` — view model of the preview page
- `islands/BetaMapRouteSteps.tsx` — the interactive editor
- `components/GoogleMapsPin.tsx` — the map pin icon
- `routes/beta/[...path].tsx`, `routes/beta/expand-link.ts`
- `static/beta-map-route.css` — preview-only styles

## The step

A map step is **still an ordinary Markdown link** — `[label](url)` — exactly
like the shipped Link step. Nothing new is stored in the document. What the map
step adds is a reading of that link through `lib/maps/`: if the URL is a Google
Maps place or route link, the step is shown as a **frame** of ordered stops.

- Label: editable, and _derived_ while it was never customised
  (`Lviv → Stryi → Uzhhorod`); typing a custom label keeps it.
- URL: never typed by hand. It is regenerated by `to_route_url` from the frame's
  top-to-bottom stop order, plus the chosen travel mode.
- A frame with a single stop generates a route with the origin omitted, so the
  Google Maps app starts from the current location when the link is opened.
- A route link whose origin was already implicit shows `Your location` as its
  first stop. Because the URL API expresses it only by an absent `origin`, it is
  honoured in the first position only; anywhere else the frame warns and the
  generated route leaves it out.

## Dragging

Two grips, one gesture model, always with an on-screen indication:

| Gesture                         | Indication                      | Result                                    |
| ------------------------------- | ------------------------------- | ----------------------------------------- |
| Step grip between steps         | blue insertion line             | reorder steps                             |
| Step grip over another map step | dashed frame + "Frame as stops" | the two steps become one ordered frame    |
| Stop grip inside its frame      | blue insertion line             | reorder stops (route follows immediately) |
| Stop grip over another map step | dashed frame                    | the stop moves into that frame            |
| Stop grip outside any frame     | blue insertion line             | the stop splits out as its own map step   |

Framing is _not_ the shipped text merge: values are never concatenated. Two map
steps joined keep every point, in drop order, and a repeated place at the seam
(`A→C` dropped on `C→D`) collapses into one stop. Any stop can leave the frame
again, so the grouping is reversible.

Keyboard: a focused grip moves its step or stop with `ArrowUp` / `ArrowDown`;
`Split out` and `×` buttons cover extraction and removal without a pointer.

## Adding stops

`New map step` and `Add stop` accept anything `lib/maps/` understands: a
documented `api=1` link, an interactive `/maps/place|dir|@` link, a legacy
`?q=`/`?daddr=` link, a `geo:` URI, bare `lat,lng`, or plain place text. Pasting
a _route_ link adds all of its stops at once.

Official short links (`maps.app.goo.gl`, `goo.gl/maps`) cannot be followed by
the browser, so the surface posts them to `/beta/expand-link`; the server only
dereferences URLs the parser already classified as Google short links and only
returns the result when the expansion is itself a place or route link.

## Preview caveats

- While the preview route exists, `/beta` shadows a `beta` namespace in public
  page delivery; `beta` is not in `forbidden_namespaces`, so this is a
  preview-only shadow and disappears with the route.
- Non-map sections are shown read-only in the preview; editing text, headings,
  and code blocks stays in the shipped editor.
- The draft lives in the page only. Nothing is published from `/beta`.
